# QA-008 릴리스 검증과 회귀 테스트

## 릴리스 검증 흐름

프런트·API·AI 후보 SHA와 이미지 digest, OpenAPI 기준 커밋, 환경을 기록한다. 같은 조합으로 자동 테스트 → 스테이징 회귀 → 배포 직후 확인 순서로 진행한다. 구성이나 이미지가 바뀌면 영향을 받는 항목을 다시 확인한다. 아래는 검토용 판정 기준이며 각 후보의 실행 결과는 별도 기록한다.

## 릴리스 게이트와 회귀 세트

| 시점 | 실행·증거 | 통과 기준 |
|---|---|---|
| 후보 빌드 | 프런트 타입 검사·린트·테스트·빌드, 백엔드 전체 테스트·빌드·OpenAPI 원본 대조. CI 실행 또는 로그를 후보 SHA와 연결 | 실패가 없고 번들과 원본이 일치한다. 실패를 빈 목록이나 샘플 성공으로 표시하는 경로가 없다. |
| 스테이징 기능 | QA-001의 TC-V2-01~05·07. 실제 Ingress에서 OWNER·GUEST, 노트 충돌·검색, SSE·음성, 피드·일정, PDF 및 브라우저 경계를 확인 | 각 기대 결과와 변경 영향 NFR 충족. 링크에는 합성 데이터와 안전한 추적 ID만 남긴다. |
| 보안·데이터 | QA-005 권한·출처·내부 경로, QA-006 미해결 결함, QA-007 삭제·보존 설정 확인 | 교차 계정 노출·내부 쓰기 경로 노출·데이터 유실은 배포 보류. 나머지 결함은 영향·완화·재검토일을 적어 판정한다. |
| 복구·운영 | TC-V2-06. 원본 공동 복원점, 롤백할 이미지·라우팅·DB 조합, 실제 경보 수신 기록 | 격리 복구 후 본문·첨부와 재색인 결과 확인. 재기동·복구 목표는 PRD-006·INF-009의 해당 시나리오를 적용한다. |

## 배포 후 확인과 롤백

운영자가 동일 출처 신원 확인, 개인 노트 읽기, API·AI 라우팅, 관측 신호를 확인한다. 권한 격리 실패나 저장 무결성 훼손은 쓰기·배포를 중지하고 INF-011의 해당 런북으로 전환한다. 복귀 조합에서 읽기 검증 후 복귀 시각과 영향 구간을 기록한다. 복원 시점 이후 쓰기가 있으면 영향 평가 후 복구 방법을 결정한다.
