# QA-007 개인정보와 데이터 보존

## 수집 항목과 생명주기

| 데이터·목적 | 보관 위치와 접근 | 보존·파기 및 확인 방법 |
|---|---|---|
| 신원·역할, 체험용 편집 | 인증 프록시의 세션과 앱의 신원 문맥. 체험 편집은 탭 메모리 | 로그아웃·역할 전환·새로고침 뒤 개인 캐시와 샘플 변경분을 확인한다. Service Worker에 개인 응답이 남지 않아야 한다. |
| 노트 본문·첨부·리비전 | PostgreSQL 메타데이터와 RustFS 객체. 소유자 범위 | 삭제 즉시 조회·검색에서 제외한다. 원본 정리는 배포의 NOTE_DELETED_RETENTION_DAYS와 색인 삭제 반영 상태를 확인한다. 설정 생략 시 자동 영구 정리가 비활성이다. 공유 첨부의 남은 리비전 참조를 확인한다. |
| 검색·RAG 파생 데이터 | OpenSearch·Qdrant | 원본 삭제가 두 타깃에 반영됐는지 확인하고, 재색인 후에도 문서가 복원되지 않는지 검사한다. |
| 대화·음성, 피드·일정·알림 | 개인 공간 DB, 구성된 외부 처리 공급자 | 접근은 소유자로 제한한다. 대화 이력 및 공급자 측 로그의 보존 기간·삭제 수단은 운영 설정 확인 항목이다. 음성 전송 전 실제 공급자와 처리 범위를 확인한다. |
| PDF 입력·비밀번호 | 서버 처리 시 요청별 임시 파일·처리 메모리 | 정상·실패·취소 후 잔존 시간을 PRD-006 기준과 대조한다. 비밀번호가 인자·로그에 남지 않는지 확인한다. |
| 로그·백업 | 접근이 제한된 관측 저장소와 복원 세트 | 운영자가 보관 설정·만료 방법·접근 권한을 기록한다. 백업 복원 후 이미 삭제한 데이터의 노출 여부를 재확인한다. |

## 삭제 요청과 안전성 확인

운영자가 요청자의 신원을 기존 인증 경계에서 확인한 뒤 대상·범위·접수일을 기록한다. 접근 즉시 차단, 논리 삭제, 파생 데이터 반영, 원본 정리, 백업 만료를 구분해 실제 완료한 단계만 회신한다. 검증용 기록에는 원문·암호·첨부 대신 합성 ID와 시각을 남긴다. [데이터 모델](../backend/be-006-database-erd.md) · [데이터 흐름](../architecture/arc-005-data-flow.md) · [백업과 복구](../infrastructure/inf-009-backup-recovery.md)

## 유출 대응과 운영 전 확인

노출 정황이 있으면 운영자가 영향 경로·기간·대상 범위를 확인하고 접근 제한과 필요한 비밀 교체를 수행한다. 영향받은 사용자에 대한 연락, 적용되는 보존·통지 의무와 기한은 실제 운영 주체·관할·공급자 조건을 확인해 결정한다. 로그·백업·AI 공급자별 기간이 미확정이면 릴리스 기록에 담당자와 결정 상태를 남긴다. [취약점 대응 기록](qa-006-vulnerability-management.md) · [관측 범위](../infrastructure/inf-010-observability.md)
