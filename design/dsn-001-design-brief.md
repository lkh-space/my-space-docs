# DSN-001 디자인 브리프

> v2 정식 승인본. Figma v2(디자인 시스템 및 제품 화면) 확정 시안 기준.

## Figma 탐색

시각 방향과 전체 구성은 [Figma 프로젝트 안내](https://www.figma.com/design/i4UZw9LDRw0JLSWWbrmdik/my-space-v2?node-id=0-1) 및 [디자인 시스템](https://www.figma.com/design/i4UZw9LDRw0JLSWWbrmdik/my-space-v2?node-id=7-2)에서 확인한다. 상세 분류와 node-id는 [탐색 대응표](README.md)를 따른다.

2026-11-14 정합성 작업: 모바일과 프론트 DESIGN.md는 비교 대상에서 제외한다. 전체 탐색 규칙은 [design README](README.md)를 따른다.

## 디자인 문제

공간의 지속적 기록과 도구의 일회성 실행을 하나의 제품에서 이해할 수 있어야 한다. REQ-001, REQ-002, REQ-031을 기준으로 v1 구현과 독립적으로 v2를 전면 설계한다.

## 목표와 비목표

| 구분 | 내용 | 확인 방법 |
|---|---|---|
| 목표 | 공간과 도구의 목적을 메뉴에서 구분 | 처음 보는 사용자가 노트 저장과 문서 변환 위치를 설명 |
| 목표 | 다음 행동과 처리 결과를 명확히 표시 | PDF 선택부터 다운로드까지 시안으로 따라가기 |
| 목표 | 반복 요소의 일관성 | 컴포넌트 보드와 대표 화면 대조 |
| 비목표 | 협업·유료 플랜·새로운 기능 추가 | PRD 범위 대조 |

## 대상 사용자와 사용 맥락

주 사용자와 외부 방문자 체험 계정은 [제품 개요](../product/prd-001-product-overview.md)를 따른다. 데스크톱에서는 기록·개발 작업, 모바일에서는 일정 확인·계산·빠른 실행을 고려한다. 서버 중단과 브라우저 오프라인은 구분한다.

## 범위

전체 v2 정보 구조, 디자인 시스템과 검토 완료된 비모바일 제품 화면을 다룬다. 산출물은 DSN-001~009와 Figma v2다. Stitch 검토 프로젝트는 생성·수정 이력으로 보존한다. 화면별 상태 및 실제 동작 검증 범위는 DSN-004에 구분해 기록한다. DSN-010은 확정된 결정의 변경이 생길 때 작성한다.

## 브랜드와 톤

확정된 시각 방향은 밝고 차분한 기록 공간과 명확한 작업 도구다. 한국어 중심, 한 문장 설명, 동사형 버튼. 넓은 여백과 읽기 쉬운 본문, 제한된 강조색. 현재 확정 시안은 라이트 모드이며 다크 모드 지원 범위는 미결정이다.

사용자 레퍼런스: [Craft](https://www.craft.do), [Smallpdf](https://smallpdf.com), [TDS](https://tossmini-docs.toss.im/tds-mobile/), [KRDS](https://www.krds.go.kr/html/site/index.html).
Smallpdf의 기능별 진입 구조와 KRDS의 스타일·컴포넌트·패턴 구분은 공식 페이지에서 확인했다. Craft와 TDS는 조회 시간 초과로 상세 분석이 미완료다. 현재 색상·간격은 타사 원본에서 추출한 값이 아닌 my-space 전용 규격이다. 타사 자산·코드를 복제하지 않는다.

## 제약

요구사항은 [PRD-002](../product/prd-002-requirements-scope.md), 수용 기준은 [PRD-003](../product/prd-003-user-stories.md), 품질 수치는 [PRD-006](../product/prd-006-nfr.md)를 참조한다. v2.1~v2.3은 기존 릴리스 계획의 하위 단계이며 현재 제품은 v1이다. 구현 기술·의존성은 이 문서에서 변경하지 않는다.

## 완료 기준과 일정

비모바일 디자인 시스템과 제품 화면은 사용자 검토를 완료한 Figma v2를 기준으로 한다. 문서는 승인된 시안과 정합성을 유지한다. 개별 상태·프로토타입·접근성 구현의 검증 완료 여부는 DSN-004의 기록을 따른다. 모바일 및 프론트 DESIGN.md 개정은 이번 작업에서 제외한다.
