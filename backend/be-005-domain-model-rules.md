# BE-005 도메인 모델과 비즈니스 규칙

## 기준과 범위

v2 도메인 상태·전이·비즈니스 규칙의 기준이다. 요구사항은 [PRD-002](../product/prd-002-requirements-scope.md), 동작은 [PRD-005](../product/prd-005-functional-spec.md), 저장·보정은 [ARC-005](../architecture/arc-005-data-flow.md)를 따른다. DB 필드와 ENT 번호는 [BE-006](be-006-database-erd.md), HTTP 필드는 [OpenAPI](openapi.yaml)가 기준이다. 여기의 검토안은 v1 구현 완료 상태를 나타내지 않는다.

## 도메인 객체

| 객체 | 책임 | 수명주기 |
|---|---|---|
| Folder / Tag / DocumentTag | 소유자별 폴더 트리·태그 연결 | 생성·변경·연결 해제 |
| Document / DocumentRevision | 현재 노트와 불변 리비전 | 생성·수정·과거 리비전으로 새 버전 복원·삭제 |
| FeedSource / FeedItem / FeedFilterRule | RSS 수집·본문·키워드 판정 | 수집·재평가·읽음/북마크·구독 해제 |
| ScheduleItem / ScheduleRenewal | 정기 결제·고정 만료·D-day 및 갱신 이력 | 활성·중지·갱신·삭제 |
| Notification / NotificationDelivery | 인앱 알림과 외부 전송 | 생성·읽음 / 대기·성공·실패 |
| SchedulerCheckpoint / CatchupExecution | 작업별 실행권·성공 위치·감사 이력 | 실행권 획득·처리·성공 커밋·실패 복구 |
| ChatSession / ChatMessage | 소유자별 대화·스트리밍 | 생성·완료·중단·실패 |
| NoteOutbox / RequestDedup / SearchProjection | 저장 결과 재생 및 파생 색인 복구 | 처리 중·완료·재시도·수동 복구 |
| HolidayCache | 연도별 공휴일 캐시 | 조회·갱신·오래된 데이터 표시 |

휴지통·삭제 취소는 제품 요구사항으로 확정되지 않았으므로 도입하지 않는다. '복원'은 FN-003의 리비전 기반 본문 복원이며 새 리비전을 만든다. 삭제는 즉시 사용자 조회에서 제외하되 색인 삭제를 위한 버전 표식은 유지한다.

## 상태와 전이

### 일정

유형은 `RECURRING_PAYMENT`(정기 결제), `EXPIRATION`(고정 만료), `SINGLE_DATE`(D-day·기념일)다. 보관된 활성 여부와 날짜를 기준으로 상태를 계산하며 오늘이 바뀌어도 오래된 저장 상태를 노출하지 않는다.

| 상태 | 조건 | 다음 동작 |
|---|---|---|
| PAUSED | isActive=false | 활성화하면 날짜 기준 재계산 |
| ACTIVE | 미래 날짜, 사전 알림 구간 밖 | 날짜 도래 시 DUE_SOON/DUE |
| DUE_SOON | 미래 날짜, 설정한 사전 알림 구간 안 | 알림 및 날짜 도래 |
| DUE | 대상일 당일 | 유형별 익일 처리 |
| EXPIRED | 고정 만료일 경과 | 새 만료일로 갱신 가능 |
| ELAPSED | 반복하지 않는 SINGLE_DATE 경과 | 경과 일수 표시 유지 |

정기 결제는 지난 발생분의 알림을 판별한 후 다음 미래 결제일로 전진한다(BR-022). 고정 만료는 사용자가 새 날짜를 입력할 때만 갱신한다(BR-023). 매년 반복 SINGLE_DATE는 지난 발생분 판별 후 다음 반복일을 계산한다(BR-024). 모든 유형은 중지·삭제 가능하다.

### 피드와 AI

| 객체 | 전이 | 규칙 |
|---|---|---|
| FeedSource | ACTIVE → SYNCING → ACTIVE / ERROR; ACTIVE/ERROR → PAUSED → ACTIVE | 실패하면 마지막 성공 수집 시각을 전진시키지 않음 |
| FeedItem 분류 | NORMAL / PRIORITY / EXCLUDED | 현재 활성 키워드로 재평가, 읽음/북마크와 독립 |
| ChatMessage | GENERATING → STREAMING → COMPLETED | 정상 완료 |
| ChatMessage | GENERATING/STREAMING → INTERRUPTED | 사용자 취소·연결 종료 |
| ChatMessage | GENERATING/STREAMING → FAILED | 제공자·추론 오류 |
| NotificationDelivery / Outbox 대상 | PENDING → PROCESSING → SENT; PROCESSING → PENDING/FAILED | 재시도 또는 수동 복구, 실행권 만료 회수 |

완료된 대화 메시지를 다시 GENERATING으로 되돌리지 않는다. 새 질문은 새 requestId를 사용한다. 처리 중 요청의 상태 조회/중단은 소유자 범위에서만 가능하다.

## 비즈니스 규칙

### 노트

- **`BR-001` 불변 리비전과 저장 성공** — `REQ-003`, `REQ-028`, [ADR-0008](../architecture/adr/adr-0008-note-write-consistency.md). api가 노트 생성·수정·복원·삭제를 소유한다. 새 본문은 실행별 고유 객체 키로 먼저 저장하고, DB에서 메타데이터·리비전·현재 버전·Outbox·재생 결과를 원자적으로 커밋한 뒤 성공한다. 기대 버전이 다르면 충돌이다. 동일 멱등 키 재시도는 같은 결과를 반환한다. 이전 리비전은 수정하지 않으며 복원은 새 리비전 생성이다. DB 실패 객체는 활성 작업을 제외한 유예 기간 후 정리한다.
- **`BR-002` 폴더 순환 금지** — `REQ-003`. 자신·자손으로 이동할 수 없다. 폴더와 문서·태그 소유자가 같아야 한다. 폴더 삭제는 자식 폴더 및 문서를 루트로 이동시키며 새 이름 충돌이 있으면 전체 작업을 409로 거부한다.
- **`BR-003` 제목·폴더 이름 고유성** — `REQ-003`의 구체화인 검토 제안. 같은 소유자·폴더의 미삭제 문서 제목은 앞뒤 공백 제거 후 정확히 비교해 유일하다. 폴더 이름도 같은 부모 내에서 유일하며 루트의 null 부모도 동일 범위로 취급한다. DB 제약으로 동시 요청을 방어한다.
- **`BR-004` 파생 색인 복구** — `REQ-003`, `REQ-011`, `REQ-028`, ADR-0008. 검색 반영은 저장 성공 이후 비동기 처리다. OpenSearch 실패로 이미 저장된 노트에 500을 반환하지 않는다. api Outbox가 OpenSearch 반영과 RabbitMQ publisher confirm을 각각 추적한다. ai는 Qdrant 반영과 실행권 세대에 따른 조건부 처리 기록 후 ack한다. 이벤트에는 eventId, ownerId, documentId, revision, UPSERT/DELETE, 객체 참조가 있다. 동일 문서의 처리 실행권을 직렬화하고 이미 반영된 버전 이하는 무시한다. 실행권 만료 뒤 지연 쓰기는 이 검사만으로 막을 수 없으므로 아래 BR-004 보완의 버전별 키·조회 검증·고아 정리를 함께 적용한다. DELETE 표식은 오래된 UPSERT가 검색과 RAG에 노출되는 것을 막는 DB 기준이다. 일시 실패는 지수 지연으로 재시도하고 상한 소진 시 FAILED·운영 알림·명시적 재처리를 사용한다. 구체 재시도 횟수·타임아웃·보존 기간은 배포 전 설정으로 검증한다.

### 피드

- **`BR-010` 중복 수집** — `REQ-004`. 같은 sourceId의 guid 또는 정규화 URL을 중복 키로 사용한다. 주기·수동·Catch-up 수집은 같은 실행권과 중복 제약을 적용한다. 삭제된 출처에서 진행 중이던 작업은 결과 커밋을 중단한다.
- **`BR-011` 키워드 우선순위** — `REQ-005`. 제외 규칙이 포함 규칙보다 우선한다. 활성 포함 규칙의 가중치를 합산해 PRIORITY 정렬에 사용하고 제외 결과는 EXCLUDED 목록으로 분리한다. 규칙 수정·활성 전환·삭제 시 기존 글도 재평가한다. 키워드는 앞뒤 공백 제거·대소문자 무시로 정규화하여 종류와 관계없이 중복 등록을 거부한다. 읽음·북마크는 목표 불리언 값을 지정한다.
- **`BR-012` 본문 추출 실패 대체** — `REQ-004`. RSS 본문이 부족한 글을 열 때 정제 본문 추출을 시도하고 캐시한다. 실패하면 RSS 요약과 원본 링크를 제공한다. 외부 URL 안전성 검증·시간/크기 제한을 적용하며 실패가 전체 피드 조회를 막지 않는다.

### 날짜·알림·Catch-up

- **`BR-020` 날짜 공통 규격** — `REQ-006`, `REQ-007`, `REQ-008`, `REQ-010`. 일자는 Asia/Seoul 달력 날짜이며 시각은 UTC로 저장한다. 날짜 차이는 달력 일수로 계산한다. 알림 간격은 중복 없는 0 이상의 정수 목록이며 유형별 발생일을 기준으로 계산한다. 중지된 일정은 새 알림을 만들지 않는다.
- **`BR-021` Catch-up 원자성·전송 분리** — `REQ-009`, `REQ-010`, ARC-005. 기동 및 주기 작업은 작업별 lastRunAt 이후 누락 발생분을 판별한다. `(scheduleItemId, targetDate, daysBefore)`가 인앱 알림 중복 키다. 일정 전진·인앱 알림 생성·해당 작업의 성공 체크포인트를 같은 트랜잭션에 커밋한다. RSS는 별도 체크포인트이며 실패 시 전진하지 않는다. 작업 키별 실행권과 만료 회수로 동시 실행을 제어한다. 외부 Slack은 커밋 후 PENDING 전송을 처리하며 SENT/FAILED·재시도·실행권을 저장한다. 전송 후 완료 기록 전 장애에서는 외부 중복이 가능하므로 정확히 한 번 전달을 보장하지 않는다. RSS 원천에서 사라진 과거 글의 복구도 보장하지 않는다.
- **`BR-022` 정기 결제** — `REQ-006`. 월간·연간·주간·N개월과 기준일을 보존한다. 월말 부족 날짜는 그 달 말일로 보정하되 다음 달 계산은 원 기준일로 돌아간다. 놓친 발생일을 처리한 뒤 오늘 이후 첫 예정일로 전진한다. 월 합계는 월간 금액, 연간/12, 주간×52/12, N개월 금액/N을 원 단위 반올림하여 합산한다.
- **`BR-023` 고정 만료 갱신** — `REQ-007`. 현재 날짜보다 뒤가 아니라 **기존 만료일보다 뒤인 새 만료일**을 입력받는다. 이전·새 날짜와 갱신 시각을 이력에 남기고 새 기준으로 상태를 계산한다. EXPIRED 상태도 갱신할 수 있다. 같은 요청의 expectedVersion은 중복 갱신을 막는다.
- **`BR-024` D-day·기념일** — `REQ-008`. 반복하지 않으면 당일 D-Day, 이후 D+N을 유지한다. 매년 반복이면 원 월·일과 최초 연도를 보존하며 다음 발생일과 반복 횟수를 계산한다. 2월 29일은 평년 2월 28일로 표시하고 윤년에는 다시 원 날짜를 쓴다.

### AI·방문자·도구

- **`BR-030` 대화와 중단** — `REQ-011`. 텍스트와 PTT를 지원한다. 취소·연결 종료는 추론/TTS를 중단하고 INTERRUPTED, 제공자 오류는 FAILED로 기록한다. Save to Markdown은 api 저장 경로를 사용하며 완료된 본인 메시지만 저장한다.
- **`BR-031` RAG 격리** — `REQ-011`, `REQ-030`. ownerId와 embeddingModel로 필터링하고 삭제/오래된 버전을 제외한다. 모델별 차원·거리·임계값·topK는 함께 검증한다. 근거 없는 고정 유사도 0.75·상위 3개를 제품 요구사항으로 단정하지 않는다.
- **`BR-040` 방문자 체험** — `REQ-026`, `REQ-030`, `NFR-006`, [ADR-0007](../architecture/adr/adr-0007-visitor-browser-state.md). 샘플 읽기만 서버에서 수행하고 변경은 브라우저 메모리에서 수행한다. 새로고침·초기화·탭 종료 시 폐기한다. 주 사용자 저장소·검색·외부 AI·Slack·색인에 접근하지 않는다. 미인증은 방문자가 아니다.
- **`BR-050` PDF 일회성 처리** — `REQ-012`, `NFR-006`, [ADR-0009](../architecture/adr/adr-0009-local-tool-execution-contract.md). 입력 총합 20MB 이하의 지원되는 비암호화 작업은 로컬, 암호화 포함·20MB 초과·엔진 미지원은 작업 전체를 서버로 위임한다. 최대 20개·개별 50MB·총합 100MB를 양쪽에서 검증한다. 손상·범위 오류를 무조건 서버로 재시도하지 않는다. 서버 임시 파일은 완료·오류·취소·연결 종료 finally 및 기동/주기 청소로 제거하고 실행 중 작업은 제외한다. 비밀번호는 로그·명령행 인자·디스크에 남기지 않는다.

## 일관성 경계

| 작업 | 원자적으로 커밋할 범위 | 외부 처리 |
|---|---|---|
| 노트 저장/복원 | 기대 버전 검사, Document, Revision, Tag 연결, Outbox, RequestDedup 결과 | 본문 먼저 업로드; 색인은 커밋 후 |
| 노트 삭제 | 삭제 표식·버전 증가·DELETE Outbox | 색인 제거 후 객체 정리; 오래된 이벤트는 표식으로 차단 |
| 일정 갱신 | expectedVersion 검사, ScheduleItem, ScheduleRenewal | 다음 알림 판정은 새 날짜 기준 |
| 일정 Catch-up | 실행권 검증, 일정 전진, 중복 없는 Notification/Delivery, lastRunAt, 감사 성공 | Slack 발송은 커밋 밖 |
| RSS 수집 | 수집 결과 upsert와 해당 작업 성공 시각 | 외부 요청은 트랜잭션 밖; 삭제/실행권 재검증 |

트랜잭션 격리 수준만 쓰고 안전성을 보장했다고 보지 않는다. unique 제약·조건부 버전 갱신·작업별 잠금/실행권을 결합한다. [BE-006](be-006-database-erd.md)에 제약과 상태를 연결하고, 위반 응답은 [BE-013](be-013-error-handling.md)을 따른다.

## BR-004 보완 — 실행권 만료와 오래된 색인 쓰기

실행권은 중복 작업을 줄이는 수단이며, 외부 저장소 쓰기의 원자적 fencing을 대신하지 않는다. 기존 저장 성공·Outbox·메시지 소유권은 ADR-0008을 유지한다.

1. 이벤트의 documentId·revision과 불변 본문 키를 묶는다. OpenSearch 문서 키는 `(documentId, revision)`, Qdrant point 키는 `(documentId, revision, embeddingConfigId, chunkId)`로 결정적으로 생성한다. embeddingConfigId는 모델·청킹 설정 변경도 구분한다. 서로 다른 버전이 같은 키를 덮어쓰지 않는다. 같은 키의 재시도는 같은 불변 입력을 사용한다.
2. 반영 직전 소유자·현재 버전·삭제 여부·실행권을 재확인한다. 반영 후 `search_projections`는 lease_owner·lease_generation·미만료 조건 및 적용 버전 단조 증가 조건을 모두 만족할 때만 갱신한다. 실행권 획득마다 generation을 증가시킨다. 조건부 갱신 실패 시 해당 작업은 완료를 선언하거나 새 실행권을 해제하지 않는다.
3. 검색 색인은 후보 ID·버전만 제공한다. api 검색 및 ai RAG 모두 PostgreSQL에서 현재 소유자·미삭제·현재 revision을 확인한 후보만 사용한다. RAG는 모델에 원문을 전달하기 전에 검증하고, 화면 응답/인용을 반환하기 전에도 검증한다. 확인 실패·DB 오류는 fail-closed이며 오래된 내용으로 대체하지 않는다. 필터 후 결과가 적으면 제한된 추가 후보 조회 또는 결과 부족으로 처리한다.
4. 삭제 표식은 DB 커밋 시점부터 조회·RAG에서 제외한다. 파생 저장소 삭제는 이벤트 revision 이하로 범위를 제한해 이후 버전을 지우지 않는다. 오래된 작업자가 삭제 후 데이터를 다시 써도 조회 검증을 통과하지 못한다. 정리 작업은 현재 DB 버전·삭제 표식과 대조해 늦게 생긴 고아 색인도 반복 제거한다. 삭제 완료는 이후 오래된 쓰기가 물리적으로 불가능하다는 뜻이 아니다.
5. lease 만료 후 복귀, v4 처리 도중 v5 반영, 삭제 후 v4 지연 쓰기, 외부 반영 성공 후 DB 기록 실패, 오래된 삭제 작업의 지연 실행을 장애 주입으로 검증한다. 현재 버전이 덮어써지거나 삭제된 본문이 검색/모델 입력에 포함되면 실패다. 조회는 마지막 DB 검증 시점을 기준으로 하며 이미 외부 모델로 전송된 입력을 소급 회수한다고 보장하지 않는다.

물리 필드·키는 [BE-006](be-006-database-erd.md)을 따른다. lease 검사만으로 위 조건을 대체하지 않는다.

## BR-001 보완 — 리비전별 첨부 보존과 정리

노트 저장·복원 시 본문이 참조하는 첨부 ID 전체를 검증하고 리비전별 참조(ENT-022)를 본문 리비전·현재 버전·Outbox와 같은 DB 트랜잭션으로 기록한다. assetIds는 새 리비전의 전체 참조 집합이며 Markdown 내부 첨부 참조와 일치해야 한다. 다른 소유자 첨부와 다른 문서에 귀속된 첨부는 연결하지 않는다. 외부 이미지 URL은 영속 첨부로 간주하지 않는다.

현재 본문에서 이미지를 제거해도 보존 중인 과거 리비전의 참조는 유지한다. 복원은 원본 리비전의 첨부 집합을 새 리비전에 복제하며 과거 리비전은 수정하지 않는다. 첨부 조회는 소유자, 부모 문서의 미삭제 상태, 보존 리비전 참조 또는 유효한 초안 업로드 상태를 검증한다. 문서가 삭제되면 객체가 남아 있어도 조회를 거부한다.

첨부 GC는 모든 보존 리비전의 참조가 0이고 활성 업로드·편집 유예가 끝난 경우에만 가능하다. 연결 트랜잭션과 GC는 같은 첨부 행을 잠근다. GC가 참조·활성 작업을 재확인하고 DELETING으로 전환한 후에는 새 연결을 거부한다. 객체 삭제 실패는 DELETING 상태에서 재시도하며 참조가 생길 수 있는 AVAILABLE로 되돌리지 않는다. 리비전 보존 기간이 끝나면 해당 참조를 제거한 후 같은 절차를 적용한다. 백업의 보존·파기는 별도 운영 정책이며 즉시 물리 삭제를 약속하지 않는다.

검증: v1 이미지 포함→v2 제거→GC→v1 복원 시 이미지 유지, 다른 소유자/다른 문서 첨부 거부, 저장과 GC 경합, 삭제 문서 첨부 조회 거부, 객체 삭제 실패 후 재시도를 확인한다.

## 피드 태그·조회와 모두 읽음 계약

피드 태그는 활성 INCLUDE 규칙에 매칭된 정규화 키워드이며 사용자가 별도로 생성하는 노트 태그가 아니다. 글의 matchedKeywords는 현재 규칙에서 계산하고 제외 규칙 우선순위는 유지한다. tag 필터는 이 집합과 정확히 일치한다. 규칙 변경 후 분류·점수·매칭 배지를 함께 재평가하며, 서버는 목록 필터와 반환 배지에 같은 평가 결과를 사용한다.

모두 읽음은 요청한 sourceId/classification/isStarred/tag 및 collectedAt <= snapshotAt 범위의 미읽음 글 전체에 적용한다. 소유자 조건은 서버가 강제하고 단일 DB 트랜잭션으로 변경한다. 페이지 크기와 무관하며 이후 수집된 글은 포함하지 않는다. 재시도는 같은 조건을 사용하며 이미 읽은 글은 다시 변경하지 않는다. snapshotAt은 서버 목록 응답 값이며 미래 시각은 검증 오류다.
