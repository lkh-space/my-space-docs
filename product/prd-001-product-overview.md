# PRD-001 제품 개요와 비전

## 이 문서는

- **목적**: `my-space` 버전 2(v2)가 사용자에게 어떤 변화를 주는지, 왜 기능과 디자인·UX를 개편하고 확장하는지, 무엇을 만들지 않는지를 정리한다. 모든 v2 기획·설계 문서의 출발점이다.
- **대상 독자**: 프로젝트 소유자, AI 에이전트
- **작성 시점**: v2 기획 시작 시점(2026-10-31). 방향이 바뀌면 갱신한다.
- **등급**: 필수 — 모든 프로젝트

## 한 문단 요약 [필수]

`my-space`는 개인이 일상과 개발 업무에서 자주 쓰는 데이터 관리 기능과 유틸리티를 일관된 UX·디자인 아래 통합한 개인 워크스페이스 웹 애플리케이션이다. v2에서는 전체 화면 디자인과 사용성을 전면 개선하고, 상위 정보 구조를 사용할수록 데이터가 쌓이는 **공간(노트, 피드, 관리, AI)**과 입력 즉시 결과를 얻는 일회성 **도구(문서, 이미지, 개발, 계산)**로 재편한다. 사용자는 외부 광고성 사이트에 민감한 파일이나 토큰을 올리지 않고 자신의 워크스페이스에서 즉시 처리하며, 기술 블로그 RSS 구독과 정기 결제일·만료일·D-day 일정까지 한곳에서 관리할 수 있다. 또한 외부 방문자가 접속해 주요 기능을 직접 둘러보고 체험할 수 있는 테스트 계정 환경을 함께 제공한다.

## 제품 비전 [필수]

외부 사이트에 데이터를 맡기거나 여러 앱을 오가지 않고, 일상과 개발 업무에 필요한 모든 기록·구독·만료 관리(공간)와 문서·이미지·개발·계산 유틸리티(도구)를 정돈된 UX의 단일 워크스페이스에서 해결하는 통합 플랫폼.

## 범위와 비목표 [필수]

- **이번에 다루는 범위**:
  - **대상 사용자**: 워크스페이스 소유자(주 사용자) 및 외부 접속 시 기능을 둘러볼 수 있는 체험용 테스트 계정 사용자.
  - **플랫폼**: 반응형 웹 애플리케이션(`apps/web`, 데스크톱·태블릿·모바일 뷰포트 지원 및 클라이언트 계산·변환 도구의 PWA 오프라인 지원)과 NestJS 기반 백엔드(`my-space-backend`).
  - **기능 및 디자인 범위**: 전반적인 UI/UX 디자인 개편, 카테고리 재편(공간/도구), 기존 4대 기능(노트, AI, PDF, DBML·NoSQL 스키마 시각화)의 구조 재배치 및 확장, 신규 공간 2종(피드, 관리), 신규 도구 11종(마크다운 일회성 변환, 이미지 압축·변환, EXIF 보기·제거, cron 해석기, 정규식 테스터·시각화, JWT 디코더, timestamp 변환, 더치페이 정산기, 연봉 실수령액 계산기, 대출·적금 계산기, 단가 비교기, 날짜·영업일 계산기), 외부 방문자용 테스트 계정 환경.
- **비목표**:
  - **실제로 사용하지 않을 기능은 만들지 않는다**: 일상과 개발 업무에서 활용 빈도가 낮거나 지속해서 쓰기 어려운 기능은 범위에서 제외한다.
  - **다중 사용자 간 협업·공유 기능은 다루지 않는다**: 체험용 테스트 계정은 제공하되, 여러 사용자가 함께 문서를 공동 편집하거나 일정을 조율·공유하는 소셜·협업 기능은 만들지 않는다.
  - **중복 기능과 과도한 파이프라인은 지양한다**: 기존 공간의 기능(예: 노트의 태그·템플릿, 버전 비교)으로 충분히 대체할 수 있는 별도 공간이나, 실사용 대비 복잡도만 높이는 도구 간 체이닝·대규모 메시지 큐 구성은 하지 않는다.

요구사항 단위의 상세 포함·제외는 [PRD-002 요구사항과 범위](prd-002-requirements-scope.md#범위-필수)가 기준이다.

## 제약과 가정 [선택]

| 제약 | 외부 방문자용 테스트 계정은 주 사용자의 개인 데이터를 열람하거나 변경할 수 없도록 격리되어야 한다 | 인증·인가 및 계정별 데이터 격리 검증 |
| 가정 | 국내 주요 기술 블로그 RSS는 본문 발췌만 제공하는 경우가 많아 원문 URL에서 본문 추출(Readability)이 가능하다고 가정한다 | 피드 수집기 프로토타입에서 주요 기술 블로그 대상 추출 테스트 |
