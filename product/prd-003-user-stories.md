# PRD-003 사용자 스토리와 수용 기준

## 이 문서는

- **목적**: [PRD-002 요구사항과 범위](prd-002-requirements-scope.md#요구사항-목록-필수)의 기능 요구사항(`REQ-001`~`REQ-026`)을 사용자 관점의 개발 단위(사용자 스토리 `US-`)로 나누고, 스토리마다 완료 여부를 판단할 수용 기준을 정한다. 사용자 스토리와 `US-` ID의 **기준 문서**다.
- **대상 독자**: 프로젝트 소유자, AI 에이전트
- **작성 시점**: [PRD-002](prd-002-requirements-scope.md) 작성 직후. 각 스토리를 구현하기 전에 수용 기준까지 확정한다.
- **등급**: 필수 — 모든 프로젝트

## 스토리 목록 [필수]

## 수용 기준 [필수]

조건 분기와 예외 처리가 중요한 핵심 스토리(`US-005`, `US-007`, `US-010`, `US-024`)는 Gherkin(Given/When/Then) 시나리오형과 체크리스트형을 함께 쓰고, 나머지 스토리는 체크리스트형으로 정의한다. [근거: 기업 공식 가이드 · GOV.UK Service Manual — Writing user stories, 공식 기술 문서 · Cucumber Gherkin Reference]

### US-001 공간/도구 네비게이션 및 디자인 개편

- [ ] 사이드바(데스크톱·태블릿) 및 하단 네비게이션/메뉴(모바일)가 `공간(노트, 피드, 관리, AI)`과 `도구(문서, 이미지, 개발, 계산)` 그룹으로 구분되어 표시된다
- [ ] 반응형 3단 뷰포트(데스크톱·태블릿·모바일)에서 개편된 디자인과 네비게이션 전환이 정상 동작한다 (`NFR-008`)

### US-002 통합 홈 대시보드 및 인앱 알림 브리핑

- [ ] 대시보드 접속 시 만료·결제 예정일이 7일 이내이거나 이미 경과한 관리 항목 목록과 건수가 상단에 표시된다
- [ ] 미열람 관심 키워드 피드 글 수, 최근 수정한 노트 목록, 도구 빠른 이동 카드가 표시된다
- [ ] 홈랩 서버가 재기동되어 Catch-up 작업이 수행된 경우, 새로 발견된 만료 도래 항목과 새 관심 피드가 인앱 알림함에 즉시 반영된다

### US-003 공간 › 노트 (마크다운 문서 관리)

- [ ] 계층형 폴더 트리와 다중 태그로 문서를 분류하고 OpenSearch 전문 검색으로 본문·제목을 검색할 수 있다
- [ ] GFM, KaTeX 수식, Mermaid 다이어그램이 실시간 프리뷰에 렌더링되고 이미지를 드래그 앤 드롭으로 첨부할 수 있다
- [ ] 문서 수정 시 리비전이 생성되며, 두 리비전 간 텍스트 Diff를 비교하고 과거 버전으로 복원할 수 있다

### US-004 공간 › 피드 RSS 수집 및 원문 열람

- [ ] RSS/Atom 피드 URL을 등록하면 피드 제목과 최근 글 목록이 수집되어 서버 DB에 저장된다
- [ ] 동일한 GUID 또는 정규화된 URL을 가진 글은 재수집 시 중복 생성되지 않는다
- [ ] RSS 본문이 요약·발췌만 제공하는 글에서 '원문 본문 보기'를 실행하면 Readability로 추출한 본문이 리더 뷰에 표시된다
- [ ] 홈랩 서버가 꺼져 있다가 다시 켜지면 마지막 수집 시각 이후의 피드를 자동으로 수집한다

### US-005 공간 › 피드 키워드 규칙 필터링 및 우선순위

- [ ] 관심 키워드와 제외 키워드를 각각 등록·삭제·활성/비활성 토글할 수 있다

```gherkin
Rule: 관심 키워드 글은 상단에 우선 노출하고 제외 키워드 글은 목록에서 숨긴다

  Scenario: 관심 키워드와 제외 키워드가 각각 다른 글에 매칭된다
    Given 관심 키워드로 "NestJS"가 등록되어 있고 제외 키워드로 "채용공고"가 등록되어 있다
    When 새 피드 글 A("NestJS 스케줄러 설계")와 글 B("하반기 개발자 채용공고"), 일반 글 C("CSS Grid 기초")가 수집된다
    Then 피드 목록 최상단에 관심 키워드 배지가 붙은 글 A가 표시되고 그 아래에 글 C가 표시되며 글 B는 기본 목록에서 숨겨진다

  Scenario: 한 글에 관심 키워드와 제외 키워드가 동시에 포함된다
    Given 관심 키워드로 "TypeScript", 제외 키워드로 "광고"가 등록되어 있다
    When 제목이나 본문에 "TypeScript"와 "광고"가 모두 포함된 글이 수집된다
    Then 제외 규칙이 우선 적용되어 해당 글은 기본 목록에서 숨겨지고 '숨김 처리된 글 보기' 필터를 켰을 때만 확인된다
```

### US-006 공간 › 관리 정기 결제(구독) 관리

- [ ] 구독 서비스명, 결제 금액(원화 또는 외화 환산액), 시작일, 결제 주기(월간/연간/주간)를 등록·수정·삭제할 수 있다
- [ ] 오늘 날짜 기준으로 다음 결제 예정일과 남은 일수(`D-N`)가 계산되어 표시된다
- [ ] 활성화된 모든 정기 결제 항목을 월 단위로 환산한 **월 구독 합계 금액**이 상단 요약 카드에 원 단위 정수로 표시된다

### US-007 공간 › 관리 고정 만료일 관리 및 갱신

- [ ] 도메인, SSL 인증서, API 키, 여권, 운전면허, 자동차 보험 등 고정 만료일 항목과 사전 알림 기준일(예: 30일 전, 7일 전, 당일)을 등록할 수 있다
- [ ] 만료일까지 남은 일수(`D-N`)가 표시되고, 만료일이 지난 항목은 경과 일수(`D+N`)와 `만료됨` 경고 상태로 강조 표시된다

```gherkin
Rule: 고정 만료일 항목은 갱신 시 새 만료일을 입력받아 상태를 갱신하고 서버 미구동 기간의 도래 일정도 누락 없이 알린다

  Scenario: 만료 임박 항목을 갱신 처리한다
    Given 도메인 항목의 만료일이 3일 남아 "만료 임박(D-3)" 상태로 표시되어 있다
    When 사용자가 '갱신 완료'를 누르고 새 만료일(1년 뒤 날짜)을 입력해 저장한다
    Then 항목 상태가 "정상"으로 바뀌고 남은 일수가 새 만료일 기준으로 다시 계산되어 표시된다

  Scenario: 홈랩 서버가 꺼져 있는 동안 만료 알림 기준일이 지났다
    Given SSL 인증서 항목의 사전 알림일이 어제였고 어제 하루 동안 홈랩 서버 전원이 꺼져 있었다
    When 오늘 홈랩 서버가 부팅되고 사용자가 웹앱에 접속한다
    Then 서버 기동 시 Catch-up 판별이 실행되어 해당 SSL 인증서가 인앱 알림함과 대시보드 '놓친 만료 알림'에 즉시 표시된다
```

### US-008 공간 › 관리 단일 날짜(D-day·기념일) 관리

- [ ] 날짜 이름, 대상 날짜, 매년 반복 여부를 등록할 수 있다
- [ ] 매년 반복이 켜진 기념일은 올해 날짜가 지나면 자동으로 내년 날짜 기준 남은 일수(`D-N`)를 표시하고, 반복이 꺼진 D-day는 목표일 이후 경과 일수(`D+N`)를 표시한다

### US-010 도구 › 문서 PDF 프론트/백엔드 하이브리드 처리

- [ ] 일반(비암호화) PDF 파일을 드롭하면 브라우저 내에서 페이지 수·파일 크기를 즉시 표시하고(`NFR-001`), 병합·분할 작업을 수행해 결과 파일을 내려받는다
- [ ] 암호화된 PDF의 암호 해제(`Unlock`) 또는 암호가 걸린 PDF가 포함된 병합·분할은 백엔드 API(`qpdf`)를 호출해 처리한다

```gherkin
Rule: 일반 PDF와 암호화된 PDF를 구분하여 브라우저와 백엔드에서 안전하게 처리한다

  Scenario: 암호로 잠긴 PDF의 암호를 해제한다
    Given 비밀번호가 설정된 PDF 파일을 `도구 › 문서`에 추가했다
    When 파일 카드에 잠금 표시와 비밀번호 입력창이 나타나고 사용자가 올바른 비밀번호를 입력한 뒤 '암호 해제'를 실행한다
    Then 백엔드 복호화 처리가 완료되어 암호가 제거된 PDF 파일이 브라우저로 즉시 다운로드된다

  Scenario: 암호화된 PDF에 잘못된 비밀번호를 입력한다
    Given 비밀번호가 설정된 PDF 파일을 추가했다
    When 잘못된 비밀번호를 입력하고 작업을 실행한다
    Then 파일 다운로드 대신 비밀번호가 일치하지 않는다는 오류 안내가 해당 파일 카드에 표시되고 재입력할 수 있다
```

### US-011 도구 › 문서 마크다운 일회성 변환

- [ ] `공간 › 노트` DB에 문서를 저장하지 않고도 즉시 HTML 파일 또는 인쇄용 PDF로 변환해 내려받을 수 있다

### US-012 도구 › 이미지 압축·리사이즈·포맷 변환 (Web Worker/WASM)

- [ ] JPEG, PNG, WebP, AVIF 이미지를 추가하고 목표 포맷(WebP, AVIF, JPEG, PNG), 품질(1~100%), 리사이즈 해상도를 설정할 수 있다
- [ ] 변환 실행 시 네트워크 업로드 없이 브라우저 Web Worker·WASM에서 처리되어 변환 중에도 화면 스크롤·클릭이 멈추지 않는다 (`NFR-002`)
- [ ] 변환 전후 파일 크기와 절감률(%)이 표시되고 변환된 이미지를 다운로드할 수 있다

### US-013 도구 › 이미지 EXIF 메타데이터 보기·제거

- [ ] JPEG 이미지를 선택하면 직접 구현한 바이너리 파서(`ArrayBuffer`/`DataView`)가 APP1(EXIF) 세그먼트와 엔디안(Little/Big Endian)을 해석해 카메라 모델, 촬영 일시, 노출값, GPS 위경도 태그를 표로 보여준다 (`NFR-001`)

- [ ] 'EXIF 제거 다운로드'를 누르면 이미지 픽셀 재인코딩(화질 저하) 없이 메타데이터 세그먼트만 제거된 깨끗한 JPEG 파일을 내려받는다

### US-014 도구 › 개발 RDB(DBML) · NoSQL 스키마 시각화 및 변환

- [ ] **RDB 모드(DBML)**: DBML 타이핑 즉시 2D 캔버스에 테이블 카드와 외래키 곡선이 렌더링되고, PostgreSQL·MySQL·SQLite·MSSQL 방언과 양방향 변환된다
- [ ] **NoSQL 모드(스키마 추론 다이어그램)**: JSON·문서 구조 데이터를 입력하면 필드별 예시 값 나열 대신 **추론된 필드 타입(`string`, `number`, `boolean`, 참조 ID 등)**과 **중첩 객체·배열(Embedded, 점선) 및 외부 참조(Reference, 실선)** 관계를 구분한 스키마 카드로 시각화한다
- [ ] 두 모드 모두 카드를 마우스로 드래그해 배치하고 SVG/PNG/JPG 이미지로 내보낼 수 있다

### US-015 도구 › 개발 cron 표현식 해석·생성기

- [ ] 5필드(분·시·일·월·요일) 또는 6필드(초 포함) cron 표현식을 입력하면 직접 구현한 토크나이저·파서가 한국어 자연어로 의미를 설명한다 (예: `"매주 월~금요일 오전 9시 30분에 실행"`) (`NFR-001`)
- [ ] 기준 시각(기본값: 현재 시각)으로부터 앞으로 실행될 다음 N회(기본 5~10회) 실행 예정 일시 목록이 순서대로 표시된다
- [ ] 원하는 반복 주기(예: 매 15분마다, 매 2시간마다, 매일 오전 9시, 매주 평일 특정 시각 등)를 선택하거나 입력하면 해당하는 표준 cron 표현식(예: `*/15 * * * *`)을 생성하고 복사할 수 있다
- [ ] 잘못된 토큰이나 범위(예: 시 필드에 `25`, 분 필드에 `70`)가 입력되면 어느 필드의 어떤 토큰이 잘못되었는지 정확한 위치와 이유를 표시한다

### US-016 도구 › 개발 정규식 테스터·시각화

- [ ] 정규식 패턴과 플래그(`g`, `i`, `m` 등)를 입력하면 직접 구현한 파서가 생성한 AST를 기반으로 문자 클래스, 수량자, 캡처 그룹, 분기(`|`) 구조를 다이어그램(철도 다이어그램 또는 트리 뷰)으로 시각화한다 (`NFR-001`)
- [ ] 테스트 문자열을 입력하면 전체 매칭 구간 하이라이트와 캡처 그룹별 추출 문자열·인덱스가 실시간으로 표시된다
- [ ] 닫히지 않은 괄호 등 문법 오류가 있으면 오류 위치를 표시한다

### US-017 도구 › 개발 JWT 디코더

- [ ] JWT 문자열(`header.payload.signature`)을 붙여넣으면 네트워크 요청을 전혀 발생시키지 않고(`NFR-006`) Base64Url 디코딩된 Header와 Payload JSON을 포맷팅해 보여준다
- [ ] Payload에 `exp`, `iat`, `nbf` 클레임이 있으면 사람이 읽을 수 있는 시각(KST 및 UTC)으로 함께 표시하고, 현재 시각 기준 **만료 여부(`유효` / `만료됨`)**와 남은 시간(또는 경과 시간)을 배지로 표시한다

### US-018 도구 › 개발 Unix timestamp ↔ 날짜 변환

- [ ] 숫자 입력 시 초(10자리)와 밀리초(13자리)를 자동 판별(또는 선택)하여 UTC 및 선택한 타임존(기본 `Asia/Seoul`)의 ISO 8601·한국어 날짜 문자열로 변환한다
- [ ] 날짜·시각과 타임존을 선택해 입력하면 초·밀리초 Unix timestamp로 역변환하며, '현재 시각 캡처' 버튼을 제공한다

### US-019 도구 › 계산 더치페이 정산기

- [ ] 참석자 목록을 등록하고 여러 건의 결제 내역(결제자, 금액, 대상 참석자 선택)을 추가할 수 있다
- [ ] 1인당 부담액, 인원별 기지출액 대비 순수 차액(받을 금액/보낼 금액) 산출 근거 표, 그리고 **최소 송금 횟수**로 정산을 끝내는 송금 지시표(`"A → B에게 15,000원 송금"`)가 함께 표시된다
- [ ] 정산 결과 전체를 메신저 공유용 텍스트 포맷으로 클립보드에 복사할 수 있는 '정산 결과 복사' 기능을 제공한다

### US-020 도구 › 계산 연봉 실수령액 계산기

- [ ] 적용 연도(세율·요율 기준 연도), 연봉(또는 월 급여), 월 비과세액, 부양가족 수(본인 포함), 20세 이하 자녀 수를 입력할 수 있다
- [ ] 국민연금(상·하한액 반영), 건강보험, 장기요양보험, 고용보험, 소득세, 지방소득세 공제액과 **월 예상 실수령액**이 원 단위로 계산되어 표시된다
- [ ] 각 공제 항목의 **적용 요율(%), 상·하한 기준, 산출 공식 및 기준 연도 법령·고시 출처**가 함께 표시되어 계산 근거를 확인할 수 있다
- [ ] 세율·요율 수치는 계산 함수 내부 하드코딩이 아니라 분리된 연도별 설정 데이터에서 읽어온다

### US-021 도구 › 계산 대출·적금 이자 계산기

- [ ] **대출 탭**: 대출 원금, 연 이자율(%), 기간(개월), 상환 방식(원리금균등 / 원금균등 / 만기일시)을 입력하면 총 이자, 총 상환액, 회차별 상환 스케줄 표(원금·이자·잔액)가 표시된다
- [ ] **적금 탭**: 월 납입액(또는 예치금), 연 이자율(%), 기간(개월), 과세 구분(일반과세 15.4% / 비과세)을 입력하면 세전 이자, 이자 과세액, 세후 만기 수령액이 표시된다
- [ ] 모든 금액 연산이 원 단위 정수 연산으로 처리되어 회차별 원금 합계가 대출 원금과 1원도 어긋나지 않으며, 적용된 **상환·이자 계산 공식과 원 단위 단수(절사·보정) 처리 기준**이 함께 표시된다

### US-022 도구 › 계산 단가 비교기 (PWA 오프라인)

- [ ] 2개 이상의 비교 품목에 대해 가격(원), 용량·크기, 수량, 단위(`g`, `kg`, `ml`, `L`, `개`, `매`)를 입력하면 같은 단위로 자동 환산(예: `1kg` → `1,000g`)하여 기준 단위(예: `100g당`, `100ml당`, `1개당`) 단가와 단위 환산 계산식을 표시한다
- [ ] 가장 저렴한 품목에 `최저가` 배지와 나머지 품목 대비 절감 비율(%)이 표시된다
- [ ] 모바일 브라우저에서 PWA로 설치하거나 네트워크를 오프라인(비행기 모드)으로 전환한 상태에서도 화면 로드와 단가 비교 계산이 정상 동작한다 (`NFR-005`)

### US-023 도구 › 계산 날짜·영업일 계산기

- [ ] 시작일과 종료일(또는 시작일 + N일/N영업일)을 입력하면 전체 일수와 주말·공휴일을 제외한 **실제 영업일 수**(또는 N영업일 뒤의 날짜)가 표시된다
- [ ] 총 달력 일수에서 차감된 주말 일수, 계산 기간 안에 포함된 법정 공휴일·대체공휴일 목록(날짜와 공휴일 이름) 및 공휴일 데이터 기준 출처(공공데이터포털 특일 정보)가 산출 근거로 함께 표시된다

### US-024 외부 방문자 테스트 계정 체험 및 주 사용자 데이터 격리

- [ ] 테스트 계정으로 로그인하면 각 공간(노트, 피드, 관리, AI)에 미리 준비된 샘플 데이터만 표시되고 모든 도구를 실행해 볼 수 있다
- [ ] 테스트 계정에서 항목을 생성·수정·삭제하면 서버 DB에는 저장하지 않고 현재 브라우저 화면(인메모리 상태)에만 즉시 반영되며, 페이지를 새로고침하면 원래의 초기 샘플 데이터 상태로 돌아간다

```gherkin
Rule: 테스트 계정은 주 사용자의 데이터와 서버 샘플 원본을 변경할 수 없다

  Scenario: 외부 방문자가 테스트 계정으로 로그인해 공간 데이터를 조회하고 글을 작성한 뒤 새로고침한다
    Given 주 사용자의 계정에 개인 노트와 구독·만료 일정이 저장되어 있다
    When 외부 방문자가 테스트 계정으로 로그인하여 `공간 › 노트`를 조회하고 새 노트를 작성해 저장한다
    Then 주 사용자의 개인 데이터는 일절 노출되지 않고 작성한 노트가 현재 화면에는 즉시 표시되지만, 페이지를 새로고침하면 서버 DB에 저장되지 않아 초기 샘플 데이터만 표시된다 (`NFR-006`)
```
