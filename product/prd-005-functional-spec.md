# PRD-005 기능 명세

## 이 문서는

- **목적**: [PRD-002 요구사항과 범위](prd-002-requirements-scope.md)와 [PRD-003 사용자 스토리와 수용 기준](prd-003-user-stories.md)을 만족시키는 각 기능(`FN-`)마다 입력, 처리 순서, 결과, 예외 상황을 정의한다. 디자인과 프론트엔드·백엔드 구현 단계에서 "이 기능이 정확히 어떻게 동작해야 하는가"를 확인하는 기준 문서다.
- **범위**: 업무 관점의 입력 항목, 처리 순서, 결과, 예외만 기술한다. 구체적인 화면 배치는 디자인(`DSN`), API 경로와 필드 타입은 백엔드(`BE`)에서 정한다.
- **대상 독자**: 프로젝트 소유자, AI 에이전트
- **작성 시점**: [PRD-002](prd-002-requirements-scope.md)·[PRD-003](prd-003-user-stories.md) 작성 직후, 화면 명세와 API 명세 확정 전.
- **등급**: 조건부 — 기능이 다양하여 입력·처리·예외 기준이 필요한 프로젝트

## 기능 상세 [필수]

### FN-001 공간·도구 구조로 네비게이션을 이동한다

- **목적**: 기능 성격(데이터 축적 vs 일회성 처리)에 따라 흔들리지 않는 2계층 메뉴 탐색을 제공한다.
- **행위자와 권한**: 사용자, 외부 방문자.
- **시작 조건**: 앱 접속 상태.
- **입력**: 선택한 상위 그룹(`공간`, `도구`) 및 하위 메뉴 항목.
- **처리 순서**:
  1. 상위 그룹별로 하위 메뉴(`공간`: 노트·피드·관리·AI / `도구`: 문서·이미지·개발·계산)를 표시한다.
  2. 사용자가 메뉴를 선택하면 해당 라우트로 이동하고 현재 활성 메뉴를 강조 표시한다.
- **결과**: 선택한 공간 또는 도구 화면이 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-007`, `NFR-008`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 정의되지 않은 경로로 진입함 | 404 안내 화면과 대시보드 복귀 링크 | `NotFoundPage` 렌더링 |

### FN-002 홈 대시보드 요약과 인앱 알림 브리핑을 조회한다

- **목적**: 앱에 들어오자마자 밀린 만료 일정과 새 관심 피드, 최근 노트를 확인하고 도구로 빠르게 진입하게 한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: 홈 대시보드 진입.
- **입력**: 없음(자동 조회) 또는 알림 읽음·확인 처리 액션.
- **처리 순서**:
  1. 백엔드에서 임박(7일 이내)·경과한 관리 공간 일정 목록, 월 구독 합계, 미열람 관심 키워드 피드 수, 최근 수정 노트 목록을 조회한다.
  2. 미확인 인앱 알림(홈랩 Catch-up으로 생성된 알림 포함)을 시간순·중요도순으로 상단 브리핑 영역에 표시한다.
  3. 도구 카테고리별 빠른 실행 카드를 표시한다.
- **결과**: 공간별 요약 카드와 인앱 알림 목록이 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-003`, `NFR-004`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 홈랩 백엔드 서버가 꺼져 있음 | 공간 요약 영역에 서버 연결 불가 안내 표시, 클라이언트 도구 바로가기는 활성 유지 | API 타임아웃 처리 후 오프라인 가능한 도구 진입 허용 |

### FN-003 마크다운 노트를 작성·탐색·버전 비교·내보내기한다

- **목적**: 개인 기술 문서와 스니펫·독서 기록을 폴더·태그·버전 이력과 함께 축적한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `공간 › 노트` 진입.
- **입력**: 제목, 마크다운 본문, 폴더(선택), 태그 목록(선택), 첨부 이미지 파일(선택), 비교할 두 리비전 번호(Diff 조회 시).
- **처리 순서**:
  1. 문서 목록 조회 시 폴더 트리·태그 필터 또는 OpenSearch 검색어로 문서를 필터링한다.
  2. 작성·수정 시 본문을 실시간 렌더링(GFM, KaTeX, Mermaid)하고, 이미지 드롭 시 RustFS에 업로드해 마크다운 이미지 문법을 삽입한다.
  3. 저장 시 문서를 갱신하고 새 버전(리비전)을 누적 생성한다.
  4. 버전 이력에서 두 버전을 고르면 텍스트 Diff를 계산해 보여주고, 복원 요청 시 선택한 과거 버전 본문으로 새 버전을 생성한다.
- **결과**: 저장된 문서 상세 뷰 또는 리비전 비교·내보내기 파일(`.md`, PDF)이 제공된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-003`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 부모 폴더를 자기 자신이나 하위 폴더로 지정함 | 순환 참조 불가 안내 | 폴더 이동 거부 |

### FN-004 기술 블로그 RSS 피드를 등록·수집하고 원문 본문을 추출한다

- **목적**: 여러 기술 블로그의 새 글을 중복 없이 수집하고 발췌문만 있는 글도 원문 본문까지 한곳에서 읽게 한다.
- **행위자와 권한**: 사용자(피드 등록·열람), 시스템(주기·기동 시 수집).
- **시작 조건**: `공간 › 피드` 진입 또는 수집 스케줄 도래.
- **입력**: RSS/Atom 피드 URL, 피드 이름(선택), 원문 추출 요청 대상 글.
- **처리 순서**:
  1. 피드 URL 등록 시 유효한 RSS 2.0 / Atom XML인지 확인하고 피드 메타데이터와 초기 글 목록을 가져온다.
  2. 글마다 고유 `guid` 또는 쿼리 파라미터를 정리한 정규화 URL을 기준으로 기존 DB 글과 대조해 중복 글은 건너뛴다.
  3. 사용자가 글을 열거나 원문 보기를 요청했을 때 RSS 본문이 발췌 수준이면 원문 URL의 HTML을 가져와 Readability 알고리즘으로 본문 아티클만 추출·정제해 저장한다.
- **결과**: 중복 제거된 피드 글 목록과 정제된 본문이 리더 뷰에 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-003`, `NFR-004`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 잘못된 URL이거나 XML 파싱에 실패함 | 유효한 RSS/Atom 피드 주소가 아니라는 안내 | 피드 등록 거부 또는 수집 오류 상태 기록 |
| 원문 사이트가 본문 추출을 차단하거나 SPA여서 본문이 비어 있음 | RSS 기본 요약문 표시 및 '원문 사이트 새 탭 열기' 버튼 안내 | 추출 실패 플래그 기록 후 원본 링크 제공 |

### FN-005 키워드 규칙으로 피드 글을 필터링하고 우선순위를 정렬한다

- **목적**: 관심·제외 키워드 규칙으로 읽을 글을 선별한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `공간 › 피드`에 수집된 글이 존재함.
- **입력**: 관심 키워드 목록, 제외 키워드 목록, 필터 보기 옵션(전체 보기 / 관심 글만 / 숨김 글 포함).
- **처리 순서**:
  1. 수집된 각 글의 제목과 본문(또는 요약)에서 제외 키워드 포함 여부를 먼저 검사한다.
  2. 제외 키워드가 하나라도 매칭되면 해당 글을 `숨김(EXCLUDED)` 상태로 분류해 기본 목록에서 제외한다 (관심 키워드가 함께 있어도 제외 규칙 우선).
  3. 제외되지 않은 글 중 관심 키워드가 매칭된 글을 `우선(PRIORITY)` 상태로 분류하고 매칭된 키워드 배지를 부착해 목록 최상단 그룹에 배치한다.
  4. 나머지 일반 글은 발행일 최신순으로 그 아래에 배치한다.
- **결과**: 관심 키워드 글이 최상단에, 일반 글이 그 아래에 표시되고 제외 키워드 글은 숨겨진다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-003`

### FN-006 정기 결제(구독) 일정을 관리하고 월 합계를 계산한다

- **목적**: 공통 날짜 모델 중 `정기 결제(시작일 + 고정 주기)` 유형을 관리하고 매달 나가는 고정 구독료를 합산한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `공간 › 관리` 진입.
- **입력**: 항목명(예: Netflix, Claude Pro), 결제 금액(원 단위 정수), 시작일(또는 기준 결제일), 결제 주기(월간 / 연간 / 주간 / N개월), 사전 알림 일수(기본 3일 전), 활성 여부.
- **처리 순서**:
  1. 시작일과 고정 주기를 기준으로 오늘 이후 가장 가까운 **다음 결제 예정일**과 남은 일수(`D-N`)를 계산한다.
  2. 오늘이 결제일을 지나면 다음 주기 날짜로 자동 전진시킨다.
  3. 활성 상태인 모든 정기 결제 항목의 금액을 월 단위로 환산(연간은 `÷ 12`, 주간은 `× 52 ÷ 12` 후 원 단위 반올림)하여 **월 구독 합계 금액**을 산출한다.
- **결과**: 항목별 다음 결제일·남은 일수와 전체 월 구독 합계가 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-003`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 매월 31일이 시작일인데 이번 달이 30일(또는 28/29일)까지밖에 없음 | 해당 월의 말일(30일 또는 28/29일)로 다음 결제일 표시 | 말일 보정 규칙 적용 |

### FN-007 고정 만료일 일정을 관리하고 만료일을 갱신한다

- **목적**: 공통 날짜 모델 중 `만료(고정 만료일)` 유형인 도메인, SSL 인증서, API 키, 여권, 운전면허, 보험 만료일을 추적한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `공간 › 관리` 진입.
- **입력**: 항목명, 분류(도메인/인증서/키/신분증/보험/기타), 고정 만료일, 사전 알림 기준일 목록(예: 30일 전, 7일 전, 1일 전), 갱신 시 새 만료일.
- **처리 순서**:
  1. 고정 만료일과 오늘 날짜의 차이로 남은 일수(`D-N`) 또는 경과 일수(`D+N`)를 계산한다.
  2. 사전 알림 기준일에 도달하면 `만료 임박` 상태로, 만료일이 지나면 `만료됨` 상태로 표시한다.
  3. 사용자가 '갱신 완료'를 누르고 새 만료일을 입력하면 기존 만료일을 갱신 이력으로 남기고 새 만료일 기준으로 남은 일수와 상태를 초기화한다.
- **결과**: 남은 일수·경과 일수 및 만료 임박/만료됨 경고가 표시되고, 갱신 시 새 만료일로 업데이트된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-003`, `NFR-004`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 갱신 시 입력한 새 만료일이 현재 만료일보다 과거임 | 새 만료일은 기존 만료일 이후여야 한다는 확인 안내 | 유효성 검사 실패 표시 |

### FN-008 단일 날짜(D-day·기념일)를 관리한다

- **목적**: 공통 날짜 모델 중 `단일 날짜(고정 날짜 + 매년 반복 선택)` 유형인 D-day와 기념일을 관리한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `공간 › 관리` 진입.
- **입력**: 제목, 기준 날짜, 매년 반복 여부(반복 / 단일), 사전 알림 일수.
- **처리 순서**:
  1. `매년 반복`이 꺼진 단일 D-day는 목표일 전이면 `D-N`, 당일이면 `D-Day`, 지난 뒤면 `D+N(경과)`로 표시한다.
  2. `매년 반복`이 켜진 기념일은 올해 날짜가 지나면 자동으로 다음 해 같은 월·일을 기준으로 `D-N`을 계산하고 몇 주년(또는 몇 번째 반복)인지 함께 표시한다.
- **결과**: D-day·기념일 카드와 남은/경과 일수가 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-003`

### FN-009 홈랩 서버 기동·스케줄 시 누락된 피드 수집과 만료 판별을 보정(Catch-up)한다

- **목적**: 24시간 상시 구동되지 않는 홈랩 서버가 꺼져 있던 동안 지나간 RSS 수집과 만료·결제 알림을 재기동 시 누락 없이 복구한다.
- **행위자와 권한**: 시스템(백엔드 스케줄러 및 애플리케이션 부팅 훅).
- **시작 조건**: 백엔드 서버 기동 완료 시점(`OnApplicationBootstrap`) 및 서버 구동 중 주기 크론 도래 시점.
- **입력**: DB에 저장된 작업별 `마지막 성공 실행 시각(lastRunAt)`과 현재 시각.
- **처리 순서**:
  1. 서버 기동 후 30초 이내에 DB에서 만료·결제 판별 작업과 RSS 피드 수집 작업의 `lastRunAt`을 조회한다.
  2. `lastRunAt` 이후부터 현재 시각 사이에 도래했거나 경과한 모든 관리 공간 일정(정기 결제일, 고정 만료일 사전 알림일·당일, D-day)을 스캔한다.
  3. 아직 발송·생성되지 않은 도래 일정에 대해 인앱 알림 레코드를 생성하고, 설정된 외부 알림 채널 어댑터가 있으면 호출한다.
  4. `lastRunAt`으로부터 수집 주기가 지난 RSS 피드들을 비동기 백그라운드 큐로 순차 수집(`FN-004`, `FN-005`)한다.
  5. 보정 실행이 끝나면 `lastRunAt`을 현재 시각으로 갱신한다.
- **결과**: 서버가 꺼져 있던 기간의 만료 알림과 새 피드가 인앱 알림함·대시보드에 반영된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-004`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 부팅 직후 외부 인터넷 연결이 아직 준비되지 않아 RSS 수집에 실패함 | 대시보드에 마지막 성공 수집 시각 표시 및 재시도 예정 안내 | 만료 일정 DB 판별은 즉시 완료하고, RSS 수집만 `lastRunAt`을 갱신하지 않은 채 다음 주기에 재시도 |

### FN-011 PDF를 클라이언트·백엔드 하이브리드로 병합·분할·암호 해제한다

- **목적**: 일반 PDF는 브라우저에서 빠르게 처리하고, 순수 JS로 복호화가 불가능한 암호화 PDF는 백엔드(`qpdf`)로 안전하게 처리한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 문서`의 PDF 도구 진입.
- **입력**: 작업 모드(병합 / 범위 분할 / 낱장 분할 / 암호 해제), PDF 파일(1~20개, 개당 최대 50MB, 총합 최대 100MB), 페이지 범위 문자열(범위 분할 시), 비밀번호(암호화된 PDF인 경우).
- **처리 순서**:
  1. 파일 드롭 시 PDF 헤더(`%PDF-`)와 파일 크기를 검증하고 암호화 여부를 확인한다.
  2. **비암호화 일반 PDF**: 브라우저 내에서 즉시 페이지 수와 파일 정보를 표시하고, 병합·분할 요청 시 클라이언트에서 처리(또는 대용량·복합 작업 시 백엔드 위임)하여 결과 파일을 다운로드한다.
  3. **암호화된 PDF**: 파일 카드에 비밀번호 입력창을 노출하고, 작업 실행 시 파일을 비밀번호와 함께 백엔드로 전송한다.
  4. 백엔드는 비밀번호를 CLI 인자가 아닌 표준 입력(`stdin`)으로 `qpdf`에 주입해 복호화·병합·분할을 수행하고, `try-finally`로 임시 파일을 즉시 삭제한 뒤 결과 스트림을 반환한다.
- **결과**: 병합된 PDF, 범위 추출 PDF, 낱장 분할 ZIP, 또는 암호가 제거된 PDF 파일이 다운로드된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-003`, `NFR-006`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 암호화된 PDF인데 비밀번호가 틀림 | 해당 파일 카드에 비밀번호 불일치 오류 표시 | `PDF_INVALID_PASSWORD` 반환 및 임시 파일 즉시 삭제 |
| 단일 50MB 또는 총합 100MB 초과 파일 선택 | 파일 크기 제한 초과 안내 | 업로드 차단 (`413 Payload Too Large`) |
| 잘못된 페이지 범위(예: 총 5페이지인데 `1-8` 또는 `5-2`) 입력 | 유효한 페이지 범위를 입력하라는 인라인 오류 | 실행 차단 (`PDF_INVALID_PAGE_RANGE`) |

### FN-013 이미지를 브라우저(Web Worker·OffscreenCanvas)에서 압축·리사이즈·포맷 변환한다

- **목적**: 서버 업로드와 별도 WASM 바이너리 배포 없이 브라우저 Web Worker와 `OffscreenCanvas`로 대용량 이미지를 메인 스레드 멈춤 없이 압축·변환한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 이미지`의 이미지 변환 도구 진입.
- **입력**: 원본 이미지 파일(JPEG, PNG, WebP, AVIF), 목표 포맷(WebP / AVIF / JPEG / PNG; 브라우저 미지원 코덱은 WebP/PNG로 폴백), 품질(1~100), 리사이즈 가로·세로 픽셀(비율 유지 옵션 포함).
- **처리 순서**:
  1. 이미지 변환 화면 진입 또는 첫 변환 요청 시 Web Worker와 `OffscreenCanvas` 변환 모듈을 지연 로딩(Lazy Load)한다.
  2. 원본 이미지 버퍼를 `Transferable`(`ArrayBuffer`)로 Web Worker에 전달한다.
  3. Worker 스레드 내부에서 리사이즈와 목표 포맷(WebP/AVIF 등) 인코딩을 수행하고 진행률을 메인 스레드로 보낸다.

- **결과**: 압축·리사이즈·포맷 변환된 이미지 파일과 전후 용량 비교가 표시된다.

| 지원하지 않는 파일 포맷이나 손상된 이미지 선택 | 지원 포맷(JPEG, PNG, WebP, AVIF) 안내 메시지 | Worker 전달 전 MIME·매직바이트 검증 후 차단 |

### FN-014 JPEG 이미지의 EXIF 메타데이터를 직접 파싱해 조회하고 제거한다

- **목적**: 외부 라이브러리 없이 JPEG 바이너리 세그먼트(`ArrayBuffer`, `DataView`, 엔디안)를 직접 파싱해 EXIF를 읽고, 화질 손실 없이 메타데이터 세그먼트만 제거한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 이미지`의 EXIF 도구 진입.
- **입력**: JPEG 이미지 파일.
- **처리 순서**:
  1. 파일을 `ArrayBuffer`로 읽고 `DataView`로 JPEG SOI 마커(`0xFFD8`)를 확인한다.
  2. 세그먼트 마커를 순회하며 `APP1`(`0xFFE1`) 세그먼트와 `"Exif\0\0"` 헤더를 찾는다.
  3. TIFF 헤더의 바이트 순서(`0x4949` Little Endian / `0x4D4D` Big Endian)를 판별하고 IFD0, Exif IFD, GPS IFD 오프셋을 따라가며 태그(제조사, 모델, 촬영 일시, 조리개, 셔터 속도, ISO, GPS 위도·경도 등)를 읽어 표로 표시한다.
  4. 'EXIF 제거' 요청 시 픽셀 데이터(`SOS` 세그먼트 이후)는 건드리지 않고 `APP1`(EXIF) 등 메타데이터 세그먼트 바이트 구간만 잘라낸 새 `Blob`을 조합해 즉시 다운로드한다.
- **결과**: 파싱된 EXIF 태그 표(위치 정보 포함 여부 강조)와 메타데이터가 제거된 무손실 JPEG 파일이 제공된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-006`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| JPEG 파일이지만 APP1(EXIF) 세그먼트가 없음 | "이 이미지에는 EXIF 메타데이터가 없습니다" 안내 | 정상 파일로 표시하되 태그 표는 비움 |
| JPEG가 아닌 파일(`0xFFD8` 미일치) 입력 | JPEG(`.jpg`, `.jpeg`) 파일만 EXIF 직접 파싱을 지원한다는 안내 | 파싱 중단 및 안내 표시 |

### FN-015 RDB(DBML)와 NoSQL 스키마를 실시간 2D 다이어그램으로 시각화하고 변환한다

- **목적**: RDB(DBML 코드)와 NoSQL(JSON·문서 구조 데이터)의 스키마를 실시간 2D 다이어그램으로 탐색·이미지 추출하고, SQL DDL 또는 타입·스키마 정의와 변환한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 개발`의 스키마 시각화 도구 진입.
- **입력**: 모드 선택(RDB DBML / NoSQL 스키마 추론), DBML·SQL 코드 또는 NoSQL 문서(JSON·YAML) 입력, 대상 SQL 방언(PostgreSQL / MySQL / SQLite / MSSQL), 이미지 내보내기 설정(SVG/PNG/JPG, 1x/2x/3x).
- **처리 순서**:
  1. **RDB 모드**: 에디터 입력 즉시 브라우저 파서가 테이블·컬럼·외래키를 추출해 우측 2D 캔버스에 카드와 베지어 곡선을 렌더링한다.
  2. **NoSQL 모드**: 입력된 JSON·문서 데이터에서 필드별 원시 값 대신 데이터 타입(`string`, `number`, `boolean`, 참조 ID 등)을 추론하고, 배열 내 객체들의 공통 필드를 단일 서브도큐먼트 스키마 카드로 묶어 내포 관계(Embedded, 점선)와 외부 참조 관계(Reference, 실선)로 구분해 2D 캔버스에 렌더링한다.
  3. 카드 드래그 이동, 줌·패닝, 검색 하이라이트, `Ctrl+S` 로컬 임시 저장(`localStorage`)을 처리한다.
  4. 변환 요청 시 RDB는 선택한 방언의 SQL DDL과 양방향 변환하고, 이미지 내보내기 요청 시 다이어그램 파일을 생성한다.
- **결과**: 실시간 RDB·NoSQL 2D 스키마 다이어그램, 변환된 SQL/DBML 코드, 내보낸 이미지 파일이 제공된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| DBML 또는 JSON 문법 오류가 있는 상태로 타이핑 중 | 상태바에 문법 오류 위치 표시, 직전 유효한 스키마 카드는 캔버스에 유지 | 부분/직전 파싱 결과 유지 |

### FN-016 cron 표현식을 직접 파싱해 자연어로 설명하고 원하는 주기의 cron 표현식을 생성한다

- **목적**: 직접 작성한 토크나이저·파서로 cron 식을 해석해 한국어 설명과 향후 실행 예정 시각을 보여주고, 사용자가 원하는 주기를 지정하면 표준 cron 표현식을 생성한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 개발`의 cron 해석·생성기 진입.
- **입력**: cron 표현식 문자열(해석 모드) 또는 반복 주기 조건(간격/주기 선택 및 시각 지정, 생성 모드), 기준 타임존(기본 `Asia/Seoul`), 계산할 횟수(기본 5~10회).
- **처리 순서**:
  1. **해석 모드**: 입력 문자열을 공백 기준으로 분리하고 각 필드(초·분·시·일·월·요일)의 토큰(`*`, `,`, `-`, `/`, 숫자, 요일·월 약어)을 직접 구현한 토크나이저로 분해한다.
  2. 각 필드의 허용 범위(분 `0-59`, 시 `0-23`, 일 `1-31`, 월 `1-12`, 요일 `0-7`)를 검증하고 유효한 값 집합(Set)과 AST 노드로 파싱한다.
  3. AST 노드를 조합해 한국어 자연어 문장(예: `"매월 1일, 15일 오전 09:00에 실행"`)을 생성하고 기준 시각부터 다음 실행 시각 N개를 순차 계산한다.
  4. **생성 모드**: 사용자가 지정한 주기 유형(매 N분, 매 N시간, 매일/매주/매월 특정 시점 등)에 따라 각 필드의 토큰 값을 조합해 표준 5필드 cron 표현식(예: 매 15분 반복 시 `*/15 * * * *`)을 생성하고 즉시 해석 결과와 다음 실행 예정 시각을 함께 갱신한다.
- **결과**: 한국어 자연어 해석 문장, 다음 N회 실행 일시 목록, 생성된 cron 표현식 문자열(클립보드 복사 가능)이 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-005`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 필드 개수가 5개·6개가 아니거나 허용 범위를 벗어난 값(예: 분에 `65`, 달력에 없는 `2월 31일`) 입력 | 어느 필드의 어떤 토큰이 잘못되었는지 하이라이트 및 한국어 원인 안내 | 오류 토큰 위치 표시 |

### FN-017 정규식을 AST로 파싱해 구조를 시각화하고 매칭 결과를 검증한다

- **목적**: 직접 구현한 정규식 파서로 AST를 만들어 구조를 눈으로 확인하고 테스트 문자열 매칭 결과를 검증한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 개발`의 정규식 테스터 진입.

- **처리 순서**:
  1. 정규식 패턴을 렉서(토크나이저)로 토큰화하고 재귀 하강 파서(Recursive Descent Parser)로 AST(그룹, 캡처/비캡처, 선택 분기 `|`, 수량자 `*+?{n,m}`, 문자 클래스 `[...]`, 앵커 `^$`, 이스케이프 시퀀스)를 생성한다.
  2. 생성된 AST를 시각적 다이어그램(철도 다이어그램 또는 계층 트리)과 노드별 한국어 설명으로 렌더링한다.
  3. 테스트 문자열에 대해 정규식을 실행해 전체 매칭 구간 하이라이트와 각 캡처 그룹(번호·이름)별 추출 값 및 시작·끝 인덱스를 표시한다.
- **결과**: 정규식 AST 시각화 다이어그램과 테스트 문자열 매칭·캡처 그룹 표가 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-005`

### FN-018 JWT 토큰을 로컬에서 디코딩하고 만료 여부를 검증한다

- **목적**: 외부 사이트에 토큰을 붙여넣지 않고 브라우저 로컬에서만 JWT 구조를 디코딩하고 만료 여부를 확인한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 개발`의 JWT 디코더 진입.
- **입력**: JWT 문자열(`header.payload.signature`), 서명 검증용 시크릿 또는 공개키(선택).
- **처리 순서**:
  1. 네트워크 요청을 일절 보내지 않고 점(`.`)으로 구분된 세 파트를 분리해 Header와 Payload를 Base64Url 디코딩(UTF-8 지원)한다.
  2. `exp`(만료 시각), `iat`(발급 시각), `nbf`(유효 시작 시각) 클레임이 있으면 타임스탬프를 KST·UTC 일시로 변환해 함께 표시한다.
  3. 현재 시각과 `exp`를 비교해 `유효(남은 시간 표시)` 또는 `만료됨(경과 시간 표시)` 상태 배지를 렌더링한다.
  4. 사용자가 선택적으로 HMAC 시크릿 등을 입력한 경우 Web Crypto API로 서명 일치 여부까지 로컬 검증한다.
- **결과**: 포맷팅된 Header·Payload JSON과 만료 상태 배지가 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-005`, `NFR-006`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 점(`.`)이 2개가 아니거나 Base64Url·JSON 디코딩에 실패함 | 올바른 JWT 형식이 아니라는 안내 | 파싱 실패 파트 안내 |

### FN-020 더치페이 최소 송금 횟수를 계산한다

- **목적**: 여러 건의 모임 결제를 최소 횟수의 송금으로 정산하고, 미정산 내역을 `공간 › 관리`로 바로 넘긴다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 계산`의 더치페이 정산기 진입.

- **입력**: 기준 연도, 급여 구분(연봉 / 월급), 금액(원), 월 비과세액(식대 등, 기본 200,000원), 부양가족 수(본인 포함 1명 이상), 20세 이하 자녀 수.
- **처리 순서**:
  1. 선택한 기준 연도의 요율 설정 데이터(국민연금 요율 및 기준소득월액 상·하한액, 건강보험 요율, 장기요양보험율, 고용보험 요율, 근로소득 간이세액표 산식 파라미터)를 로드한다.
  2. 월 환산 급여에서 비과세액을 뺀 과세 대상 월 급여액을 구한다.
  3. 각 4대 보험료와 근로소득세·지방소득세(원 단위 절사 규칙 반영)를 원 단위 정수로 계산한다.
  4. 월 급여에서 총 공제액을 차감한 **월 예상 실수령액**과 연간 실수령 총액을 산출한다.
- **결과**: 월 실수령액, 공제 합계, 항목별(국민연금·건강보험·장기요양·고용보험·소득세·지방소득세) 상세 금액 및 적용된 요율·산출 공식·법령 고시 기준 출처가 함께 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-005`

### FN-022 대출 상환금(원리금균등·원금균등)과 적금 만기 수령액을 정수 연산으로 계산한다

- **목적**: 부동소수점 오차 없이 원 단위 정수 연산으로 대출 상환 스케줄과 적금 만기 이자를 계산한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 계산`의 대출·적금 계산기 진입.
- **입력**:
  - 대출: 대출 원금(원), 연 이자율(%), 대출 기간(개월), 거치 기간(개월, 선택), 상환 방식(원리금균등 / 원금균등 / 만기일시).
  - 적금·예금: 상품 유형(정기적금 / 정기예금), 납입 금액(원), 연 이자율(%), 기간(개월), 이자 계산 방식(단리 / 월복리), 과세 구분(일반과세 15.4% / 비과세 / 세금우대).
- **처리 순서**:
  1. 모든 금액과 이자율(`basis points` 등 정수 스케일링 또는 회차별 원 단위 반올림·절사)을 정수 기반으로 연산한다.
  2. 대출 상환표 생성 시 1회차부터 마지막 회차까지의 납입 원금 합계가 대출 원금과 정확히 일치하도록 마지막 회차에서 잔여 원금을 보정한다.
  3. 적금·예금 만기 시 세전 이자, 원 단위 절사된 이자소득세·지방소득세, 세후 실수령액을 산출한다.
- **결과**: 총 상환액·총 이자·회차별 상환 스케줄 표(대출) 또는 세전/세후 만기 수령액(적금·예금)과 함께 적용된 상환·이자 산출 공식 및 원 단위 단수 처리 기준이 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-005`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |

### FN-023 용량·수량별 상품 단가를 오프라인(PWA)에서도 비교한다

- **목적**: 마트 등 모바일 현장에서 서버 연결 없이도 여러 상품의 단위당 가격을 비교해 최저가를 찾는다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 계산`의 단가 비교기 진입 (온·오프라인 모두 가능).
- **입력**: 비교할 상품 행 2개 이상(상품 별칭(선택), 가격(원), 용량·크기, 묶음 수량(기본 1), 단위 `g`/`kg`/`ml`/`L`/`개`/`매`).
- **처리 순서**:
  1. 같은 물리량 단위를 표준 기준 단위(무게는 `100g` 또는 `1g`, 부피는 `100ml`, 개수는 `1개`)로 자동 환산한다 (`총량 = 용량 × 묶음 수량`).
  2. 품목별 기준 단위당 가격을 계산해 가장 낮은 품목을 `최저가(1위)`로 표시하고, 나머지 품목들이 최저가 대비 몇 % 더 비싼지 함께 표시한다.
- **결과**: 품목별 단위당 가격 순위, 최저가 배지, 가격 차이(%) 및 단위 환산 계산식이 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-005`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 무게(`g`/`kg`) 품목과 부피(`ml`/`L`) 품목을 섞어서 입력함 | 단위 체계가 다른 품목끼리는 그룹별로 나누어 비교하거나 단위 일치 안내 표시 | 물리량 그룹 분리 표시 |

### FN-024 공휴일을 반영한 영업일 수와 D-day를 일회성으로 계산한다

- **목적**: 저장 없이 두 날짜 사이의 전체 일수와 주말·공휴일을 제외한 실제 영업일 수를 계산한다.
- **행위자와 권한**: 사용자.
- **시작 조건**: `도구 › 계산`의 날짜·영업일 계산기 진입.
- **입력**: 계산 모드(기간 영업일·일수 계산 / 기준일로부터 N영업일·N일 후 날짜 찾기), 시작일, 종료일(또는 N일), 시작일 포함 여부, 토요일·공휴일 제외 여부.
- **처리 순서**:
  1. 프론트엔드 기본 내장 정적 JSON 및 백엔드(공공데이터포털 특일 정보 API Catch-up 동기화)로부터 캐싱된 해당 연도 대한민국 법정 공휴일·대체공휴일 목록을 불러온다.
  2. 시작일부터 종료일까지의 날짜를 순회하며 주말(토·일)과 공휴일을 제외한 실제 영업일 수를 계산(또는 시작일로부터 주말·공휴일을 건너뛰며 N번째 영업일 날짜를 탐색)한다.
  3. 해당 기간에 포함된 공휴일 목록(날짜, 요일, 공휴일 명칭)과 차감 일수 산출 근거를 함께 반환한다.
- **결과**: 총 달력 일수, 실제 영업일 수(또는 목표 날짜), 제외된 주말·공휴일 목록 및 산출 근거가 표시된다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-001`, `NFR-003`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 오프라인 상태이거나 아직 공휴일 데이터가 없는 먼 미래 연도를 조회함 | 캐시된 기본 법정 공휴일로 계산되었거나 주말만 제외되었다는 안내 배지 표시 | 로컬 캐시 공휴일 우선 사용 후 안내 |

### FN-025 외부 방문자용 테스트 계정 환경을 제공하고 주 사용자 데이터를 격리한다

- **목적**: 외부 방문자가 로그인해 공간(샘플 데이터 열람 및 인메모리 쓰기 체험)과 도구를 직접 체험할 수 있게 하되, 주 사용자의 개인 데이터와 서버 샘플 원본은 철저히 분리·보호한다.
- **행위자와 권한**: 외부 방문자(테스트 계정 이용자), 시스템.
- **시작 조건**: 테스트 계정으로 인증된 세션 진입.
- **입력**: 테스트 계정 로그인 및 각 공간·도구 조작 요청.
- **처리 순서**:
  1. 인증 헤더·세션에서 현재 요청 주체가 주 사용자 계정인지 테스트 계정인지 식별한다.
  2. 테스트 계정 조회(읽기) 요청인 경우 주 사용자의 데이터 스코프에 접근하지 않고, 테스트 계정 전용으로 분리된 샘플 데이터(노트, 피드, 관리 일정)만 조회·반환한다.
  3. 테스트 계정에서 생성·수정·삭제(쓰기) 조작을 수행하면 서버 DB에는 저장하지 않고 클라이언트 브라우저 메모리 상태에만 즉시 반영하여 화면에서 동작을 확인할 수 있게 하며, 페이지 새로고침 시 서버의 초기 샘플 데이터 상태로 초기화한다.
  4. 모든 일회성 도구는 주 사용자와 동일하게 실행할 수 있도록 제공한다.
- **결과**: 방문자는 샘플 데이터와 쓰기 인터랙션·도구를 안전하게 체험하고, 주 사용자의 개인 데이터 및 서버 샘플 원본은 노출·변경되지 않는다.
- **관련 NFR**: [PRD-006](prd-006-nfr.md) `NFR-006`

| 예외 상황 | 사용자에게 보이는 것 | 시스템 처리 |
|---|---|---|
| 테스트 계정 세션에서 주 사용자 소유 리소스 ID로 직접 조회·수정을 시도함 | 권한 없음 또는 리소스를 찾을 수 없다는 안내 (`403` 또는 `404`) | 계정 스코프 불일치 차단 |
