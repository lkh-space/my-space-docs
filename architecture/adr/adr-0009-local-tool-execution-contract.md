# ADR-0009 PDF 실행 경로와 오프라인 도구 범위

## 결정 상태

승인됨 — 2026-11-19 사용자 검토 및 명시적 승인 완료.
대체 관계: ADR-0001을 대체한다. 기존 결정 본문은 역사 기록으로 보존한다.

## 맥락과 결정 동인

ADR-0001의 로컬 우선 방향은 유지하되 PDF의 크기 판단 단위와 오프라인 보장 범위를 명확히 한다. PRD-005 FN-011 및 PRD-006 NFR-005를 기준으로 한다.

## 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 작업 단위 경로 판정 + 필수 도구 프리캐시 | 다중 PDF와 최초 캐시 완료 조건이 명확 | 경로 안내와 캐시 상태 관리 필요 |
| 파일별 경로 판정 + 모든 도구 오프라인 보장 | 표현이 단순 | 혼합 병합 작업과 지연 다운로드 자산의 처리 불명확 |

## 결정

ADR-0001의 로컬 우선 실행 분리를 계승한다. 개발·계산·마크다운 변환·EXIF 파싱은 브라우저 내부에서, 이미지 압축·리사이즈·포맷 변환은 Web Worker·WASM에서 처리한다. 로컬 도구 입력은 서버로 전송하지 않는다. 다음 규칙은 PDF 예외와 캐시 보장 범위를 구체화한다.

PDF는 파일당 50MB, 요청 총합 100MB, 최대 20개를 클라이언트와 서버에서 검사한다. 비암호화 PDF 작업의 입력 총합이 20MB 이하이고 로컬 엔진이 지원하면 브라우저에서 처리한다. 암호화 파일 포함, 총합 20MB 초과 또는 로컬 엔진의 지원 불가 판정 시 작업 전체를 서버에 위임한다. '복잡한 파일'이라는 추상 조건 대신 지원 불가 오류를 기준으로 한다. 손상 파일·잘못된 범위·초과 입력은 서버로 무조건 재시도하지 않고 오류로 반환한다. 서버 전송 전에 처리 위치를 표시하고 사용자의 실행으로 전송하며 백그라운드 자동 업로드는 하지 않는다.

서버 작업은 요청별 임시 디렉터리와 실행 시간·동시성 제한을 사용한다. 완료·오류·취소·연결 종료 시 프로세스와 파일을 정리한다. 비밀번호는 CLI 인자·로그·디스크에 남기지 않는다. 정상 실행의 finally 외에도 기동 시와 주기적 정리로 이전 비정상 종료의 잔여 파일을 제거한다. 실행 중 작업은 정리 대상에서 제외한다. NFR-006의 처리 후 잔존 목표를 검증하며 서버가 꺼진 동안 실행 가능한 정리라고 주장하지 않는다.

오프라인 보장 범위는 NFR-005의 FN-016~023이다. 최초 캐시 완료 시 App Shell과 해당 도구의 실행 자산·기준 데이터를 확보한다. 설치·캐시 완료 이전 또는 브라우저 캐시 삭제 이후까지 보장하지 않는다. 이미지 WASM 등 그 밖의 자산은 도구 진입 시 지연 다운로드·캐시하며, 자산이 없으면 오프라인 이용 불가를 안내한다. 서버 PDF·공간 저장·AI·공휴일 API 갱신은 오프라인 보장에 포함하지 않는다. 인증 응답과 개인 공간 데이터는 Service Worker 정적 캐시에 넣지 않는다.

## 결과와 검증

필수 오프라인 범위를 예측할 수 있지만 추가 도구의 첫 실행은 네트워크가 필요할 수 있다. PDF 20MB 경계·혼합 암호화·총합 및 개별 제한, 취소·강제 종료 정리, 최초 캐시 후 미방문 필수 도구 진입을 검증한다.
