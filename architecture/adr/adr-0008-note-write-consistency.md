# ADR-0008 노트 저장의 단일 책임과 파생 색인 복구

## 결정 상태

승인됨 — 2026-11-19 사용자 검토 및 명시적 승인 완료.
대체 관계: ADR-0002의 프로세스 분리를 유지하고 저장 책임·복구 경계를 보완한다.

## 맥락과 결정 동인

DB·본문 객체·검색엔진·큐는 하나의 트랜잭션이 아니다. 일반 저장과 AI 저장이 서로 다른 절차를 사용하면 리비전·검색·소유자 검증이 어긋날 수 있다. DSN-009의 서버 저장 성공 표시와 PRD-006의 커밋 데이터 보존을 충족해야 한다.

## 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| api 단일 저장 절차 + 영속 이벤트 | 성공 경계 명확, 장애 후 색인 복구 가능 | 이벤트 발행·재처리 관리 필요 |
| 각 호출자가 DB·객체·색인 직접 갱신 | 초기 구현 단순 | 부분 실패와 저장 경로별 규칙 차이 발생 |

## 결정

노트 생성·수정·복원·삭제의 책임자는 api의 MarkdownModule로 통일한다. AI의 save_to_markdown은 인증된 사용자 문맥을 전달해 동일 절차를 호출한다. ai는 노트 본문·메타데이터를 직접 쓰지 않는다. 내부 호출도 사용자·역할을 검증하며 방문자 영속 쓰기를 거부한다.

본문은 변경 불가능한 리비전 객체로 먼저 저장하고, PostgreSQL 트랜잭션에서 본문 참조·리비전·현재 버전과 파생 색인용 Outbox 이벤트를 함께 커밋한다. 이 커밋 이후에만 저장 성공을 반환한다. 객체 저장 실패 시 DB를 전진시키지 않고, DB 실패 시 생긴 미참조 객체는 활성 작업을 제외한 유예 기간 후 정리한다. 응답 유실 후 재요청은 요청 식별자로 같은 결과를 반환한다. 동시 수정은 기대 버전을 검사해 충돌을 반환한다.

OpenSearch와 Qdrant는 파생 데이터다. 색인 실패는 이미 성공한 노트 저장을 되돌리지 않는다. api가 Outbox에서 전문 색인 갱신과 RabbitMQ 발행을 재시도하며, 발행 확인 전 이벤트를 완료 처리하지 않는다. ai는 Qdrant 반영 성공 후 메시지를 확인 처리한다. 소비는 최소 1회 전달을 전제로 중복에 안전해야 한다.

이벤트는 eventId·ownerId·documentId·revision·종류를 포함한다. 이전 버전 이벤트는 최신 색인을 덮어쓰지 않는다. 삭제도 버전 있는 이벤트와 삭제 표식을 유지해 늦은 수정으로 문서가 부활하지 않게 한다. 처리 실패는 제한된 재시도 후 실패 상태로 보관해 재실행할 수 있게 한다. ai 중단 시 이벤트를 보존하고 복구 후 처리한다. 재색인은 DB의 현재 버전·삭제 상태와 RustFS 원문을 기준으로 수행한다. 조회 시 소유자와 현재 삭제 상태를 재검증한다.

## 결과와 검증

저장 지연에서 검색엔진·AI 장애를 분리하지만 색인 반영은 최종 일관성이 된다. 검색 반영 지연을 저장 실패와 구분한다. 객체 저장 실패, DB 실패, 커밋 후 프로세스 종료, 발행 확인 유실, 이벤트 순서 역전·중복·삭제 후 재처리, AI 중단 후 복구를 검증한다. DB와 RustFS의 정상 재기동 보존을 함께 확인한다. 디스크 소실에 대한 백업 목표는 별도 운영 정책이며 재기동 RPO와 혼동하지 않는다.
