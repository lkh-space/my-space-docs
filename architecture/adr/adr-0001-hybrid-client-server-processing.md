# ADR-0001 민감 도구 연산의 브라우저 로컬 처리(Web Worker·WASM) 및 백엔드(qpdf) 하이브리드 분리

## 맥락과 문제 [필수]

`my-space` v2는 문서(PDF 병합·분할·암호 해제, 마크다운 변환), 이미지(무손실 압축, 리사이즈, 포맷 변환, EXIF 조회·삭제), 개발(RDB·NoSQL 스키마, cron, 정규식, JWT, 타임스탬프), 계산(더치페이, 실수령액, 대출·적금, 단가 비교, 날짜·D-day)의 총 18개 일회성 도구를 제공한다.

사용자가 이 도구들에 입력하는 데이터에는 **운영 환경 JWT 토큰, GPS 위치가 담긴 개인 사진 원본, 사내 DB 스키마, 비밀번호가 걸린 금융·계약서 PDF**처럼 민감한 데이터가 포함된다. 동시에 홈랩 서버가 꺼져 있거나 오프라인 마트 환경에서도 계산·단가 비교·개발 도구를 즉시 쓸 수 있어야 한다(`REQ-029`). 반면 AES-256 등으로 암호화된 PDF의 비밀번호 해제나 대용량 복잡 구조 PDF 조작은 순수 브라우저 JavaScript 라이브러리(`pdf-lib`)만으로 처리할 수 없는 기술적 한계가 있다. 18개 도구의 실행 위치를 어떻게 나눌 것인가?

## 결정 동인 [필수]

| 동인 | 출처 |
|---|---|
| 이미지·EXIF·JWT 등 민감 로컬 도구는 외부 네트워크 전송 `0건`을 보장해야 한다 | [ARC-002 CON-02](../arc-002-principles-constraints.md), [PRD-006 NFR-006](../../product/prd-006-nfr.md) |
| 텍스트·스키마 파서와 계산기는 입력 즉시(`150ms` 이하) 결과를 렌더링해야 하고, 고해상도 이미지 변환 중에도 UI 메인 스레드가 멈추지 않아야 한다 | [PRD-006 NFR-001, NFR-002](../../product/prd-006-nfr.md) |
| 홈랩 서버가 꺼져 있거나 모바일 오프라인 상태에서도 순수 클라이언트 도구가 `100%` 동작해야 한다 | [PRD-006 NFR-005](../../product/prd-006-nfr.md), `REQ-029` |
| 브라우저 JS로 복호화할 수 없는 암호화 PDF도 비밀번호를 안전하게 보호하면서 해제·병합·분할할 수 있어야 한다 | `REQ-012`, `REQ-030`, [PRD-006 NFR-003, NFR-006](../../product/prd-006-nfr.md) |

## 고려한 대안 [필수]

| 대안 | 장점 | 단점 | 결정 동인 충족 |
|---|---|---|---|
| **A. 브라우저 로컬 우선(Web Worker·WASM·순수 JS) + 암호화/대용량 PDF만 백엔드(`qpdf`) 위임 하이브리드** | 민감 이미지·JWT·스키마 외부 전송 `0건`. 네트워크 왕복 없이 즉각 응답. PWA 오프라인 `100%` 동작. 암호화 PDF도 네이티브 `qpdf`로 완벽 처리 | 이미지 WASM 코덱 연동과 PDF 로컬/서버 분기 로직을 프론트엔드에 구현해야 한다 | 모두 충족 |
| B. 모든 도구 연산을 백엔드 API 서버에서 일괄 처리 | 프론트엔드 번들이 가벼워지고 구현이 단순하다 | 사진·JWT를 매번 서버로 업로드해야 하므로 프라이버시 원칙(`CON-02`)에 위배되고, 홈랩 서버가 꺼지면 모든 도구가 마비된다(`NFR-005` 불충족) | 불충족 (`NFR-005`, `NFR-006` 실패) |
| C. 100% 브라우저 클라이언트에서만 처리 (백엔드 PDF 처리 제거) | 서버 의존성이 완전히 사라진다 | `pdf-lib`가 지원하지 않는 최신 암호화 PDF 해제를 구현할 수 없거나 무거운 C++ PDF 엔진 전체를 WASM으로 번들링해야 한다 | 부분 (`REQ-012` 암호화 PDF 해제 불충족) |

## 결정 [필수]

**대안 A**를 채택한다. 개발 도구 5종, 계산기 5종, 마크다운 일회성 변환, EXIF 바이너리 파서(`ArrayBuffer`/`DataView`)는 브라우저內 순수 TypeScript로 처리하고, 이미지 압축·리사이즈·WebP/AVIF 변환은 전용 **Web Worker + WASM**에서 로컬 실행하며, PDF 도구는 비암호화 일반 파일(20MB 이하)을 브라우저 `pdf-lib`로 처리하되 **암호화 PDF 해제 및 대용량·복잡 구조 PDF만 백엔드 `api` 서버의 네이티브 `qpdf`(`stdin` 비밀번호 파이프 + 임시 파일 즉시 삭제)**로 위임한다.

## 결과 [필수]

- **좋아지는 점**:
  - 사진(EXIF), JWT 토큰, DB 스키마가 브라우저 메모리를 벗어나지 않아 데이터 유출 위험이 `0`이 된다.
  - 서버 왕복 지연이 없어 파서·계산기가 즉각 반응하며, Web Worker 분리로 대용량 이미지 변환 중에도 UI 프리징이 발생하지 않는다.
  - Service Worker 프리캐싱(PWA)을 통해 홈랩 서버가 종료된 동안에도 로컬 도구들을 언제든 사용할 수 있다.
- **나빠지는 점과 트레이드오프**:
  - WebP/AVIF WASM 인코더 에셋이 추가되므로 첫 화면 로딩 속도를 해치지 않도록 이미지 도구 라우트 진입 시 지연 로드(Code Splitting & Lazy Loading)해야 한다.
  - PDF 도구에서 파일 헤더의 `/Encrypt` 여부와 파일 크기를 사전 검사해 로컬(`pdf-lib`)과 서버(`qpdf`) 경로를 분기하는 하이브리드 어댑터를 관리해야 한다.
- **후속 작업**:
  - [ARC-004 컨테이너와 주요 컴포넌트](../arc-004-containers-components.md)의 `web` 및 `api` 컴포넌트 책임 반영
  - [ARC-005 데이터 흐름](../arc-005-data-flow.md)의 `DF-01`(로컬 완결) 및 `DF-02`(하이브리드 PDF) 정의
