# ARC-002 아키텍처 원칙과 제약

> v2 설계 승인 (2026-11-20): 사용자 검토 및 승인 완료. ADR-0007~0010은 2026-11-19 승인되었다. 문서 승인으로, v2 구현·시험 완료를 의미하지 않는다. 대체된 ADR 본문은 과거 결정 기록으로 보존한다.

## 이 문서는

- **목적**: `my-space` v2 설계 결정을 내릴 때 일관되게 따르는 아키텍처 원칙(`AP-`)과 바꿀 수 없는 환경·제품 제약(`CON-`)을 정의한다. ADR([ARC-006](arc-006-adr.md))과 품질 속성 전술([ARC-008](arc-008-quality-attributes.md))의 판단 기준이 된다.
- **대상 독자**: 프로젝트 소유자, 프론트엔드·백엔드·인프라 개발자, AI 에이전트
- **작성 시점**: 시스템 개요([ARC-001](arc-001-system-overview.md)) 작성 직후, 개별 ADR 작성 전.
- **등급**: 조건부 — 홈랩 운영 제약과 프라이버시·데이터 격리 요구가 있는 실무형 프로젝트

## 아키텍처 원칙 [필수]

[근거: 기업 공식 가이드 · Microsoft Azure Well-Architected Framework — 설계 원칙 및 트레이드오프]

| ID | 원칙 | 이유 | 함의 (하는 것 / 하지 않는 것) | 관련 NFR·REQ |
|---|---|---|---|---|
| AP-01 | **브라우저 우선 처리 (Local-First for Tools)**: 서버 자원이 꼭 필요하지 않은 일회성 도구 연산은 브라우저 내부(Web Worker, WASM, 순수 JS 파서)에서 완결한다 | 민감 파일의 네트워크 유출을 원천 차단하고, 홈랩 서버 부담을 줄이며, 서버가 꺼진 오프라인 상태(PWA)에서도 도구를 즉시 사용할 수 있게 하기 위함이다 | **하는 것**: 이미지 변환·EXIF·스키마·cron·정규식·JWT·계산기를 프론트엔드에서 처리하고 Service Worker로 캐싱한다.<br>**하지 않는 것**: 로컬 처리 가능한 도구 입력값을 백엔드 API로 전송하거나 DB에 로그로 남기지 않는다 (암호화 PDF 해제·대용량 PDF만 예외). | `REQ-014`~`REQ-024`, `NFR-001`, `NFR-002`, `NFR-005`, `NFR-006` |
| AP-02 | **상태 기반 멱등 스케줄링 (State-Driven Idempotent Catch-up)**: 모든 주기적 작업(RSS 수집, 만료 알림, 정기 결제일 갱신)은 고정 시각 트리거에만 의존하지 않고 DB의 마지막 실행 상태를 기준으로 소급 실행한다 | 홈랩 서버가 며칠간 꺼져 있다가 켜져도 누락된 알림과 결제일 갱신을 정확히 복구해야 하기 때문이다 | **하는 것**: 기동 시(`OnApplicationBootstrap`) 및 주기적 루프에서 `lastRunAt`과 현재 시각을 비교해 미처리 구간을 1회씩 보정하고 중복 방지 키를 검사한다.<br>**하지 않는 것**: 서버가 특정 시각(예: 자정)에 켜져 있다고 가정하는 단순 인메모리 Cron에만 의존하지 않는다. | `REQ-009`, `REQ-028`, `NFR-004` |
| AP-03 | **고부하·장기 실행 워크로드의 프로세스 격리**: LLM 스트리밍, 음성 합성(STT/TTS), 벡터 임베딩 워커는 일반 CRUD API 프로세스와 분리한다 | AI 추론 지연이나 대용량 문서 청킹 중 메모리 스파이크가 발생해도 노트 저장·일정 관리·PDF 도구의 응답성이 흔들리지 않아야 하기 때문이다 | **하는 것**: 백엔드를 `api`(메인 API)와 `ai`(AI 워크스페이스) 두 컨테이너로 분리하고 문서 인덱싱은 `RabbitMQ` 비동기 이벤트로 연결한다.<br>**하지 않는 것**: 노트 저장 HTTP 요청 트랜잭션 안에서 동기적으로 LLM 임베딩이나 Qdrant 색인을 호출하지 않는다. | `REQ-003`, `REQ-011`, `REQ-027`, `NFR-003` |
| AP-04 | **외부 의존성 어댑터 추상화 및 우아한 성능 저하 (Graceful Degradation)**: 외부 알림 채널, LLM/음성 엔진, 공휴일 API는 인터페이스로 추상화하고 외부 장애 시 내부 핵심 기능을 유지한다 | 외부 API 한도 초과, 웹훅 장애, 원문 사이트 차단이 발생해도 사용자의 공간 데이터 조회·기록이 중단되지 않아야 하기 때문이다 | **하는 것**: 인앱 알림함 저장 후 외부 웹훅을 비동기 호출하고, 공휴일 API 실패 시 내장 기본 공휴일+DB 캐시로 폴백하며, Readability 추출 실패 시 RSS 요약본과 원문 링크를 제공한다.<br>**하지 않는 것**: 외부 시스템 호출 실패를 공간 트랜잭션 전체 실패(500 에러)로 전파하지 않는다. | `REQ-004`, `REQ-010`, `REQ-025`, `NFR-003`, `NFR-004` |
| AP-05 | **최소주의와 단일 목적 완결성 (YAGNI)**: 각 공간과 도구는 명확히 정의된 단일 책임을 완결하며, 검증되지 않은 도구 간 파이프라인 체이닝이나 과도한 추상 계층을 미리 만들지 않는다 | 1인 소유 홈랩 워크스페이스에서 불필요한 복잡도와 유지보수 부채를 방지하기 위함이다 | **하는 것**: `공간`(영속 DB 저장)과 `도구`(일회성 입출력)의 경계를 엄격히 유지하고 필요한 시점에만 공통 모듈(`libs/`)로 추출한다.<br>**하지 않는 것**: 도구 결과를 다른 도구로 자동 연결하는 워크플로 엔진이나 다중 사용자 협업 권한 체계를 구축하지 않는다. | `REQ-001`, [PRD-001 비목표](../product/prd-001-product-overview.md#범위와-비목표-필수) |
| AP-06 | **정확성 우선 금융·날짜 연산**: 금액 계산은 부동소수점 오차 없는 원 단위 정수 연산을 사용하고, 세율·요율 및 날짜 모델은 코드 로직과 기준 데이터를 분리한다 | 실수령액·대출 이자·더치페이 정산에서 1원의 오차나 연도별 세율 하드코딩으로 인한 신뢰도 저하를 막기 위함이다 | **하는 것**: 금액은 정수(BigInt 또는 안전 정수)와 명시적 절사 규칙으로 계산하고, 세율·요율은 연도별 설정 데이터로 분리하며 산출 근거를 함께 반환한다.<br>**하지 않는 것**: `number` 부동소수점 나눗셈 결과를 반올림 없이 그대로 합산하거나 세율을 계산 함수 내부에 매직 넘버로 하드코딩하지 않는다. | `REQ-021`, `REQ-022`, `REQ-023` |
