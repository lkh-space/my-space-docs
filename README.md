# my-space-docs

`my-space` 프로젝트의 제품 기획 및 전체 시스템 수준의 공통 문서를 관리하는 전용 Repository입니다.

## 목적과 역할

`my-space` 프로젝트는 프론트엔드, 백엔드, 인프라가 각각의 독립된 Repository로 구성되어 있습니다. 본 Repository(`my-space-docs`)는 개별 구현체에 종속되지 않는 프로젝트 전반의 기획, 요구사항, 상위 아키텍처 및 공통 가이드를 통합 관리합니다.

## 문서 관리 범위

### 포함하는 문서
- 제품 기획 및 비즈니스/기능 요구사항 등 프로젝트 전체 수준의 문서
- 전체 시스템 아키텍처 및 Repository 간 관계 정의
- 프로젝트 공통 문서 작성 가이드 및 표준 규칙

### 포함하지 않는 문서
- 프론트엔드, 백엔드, 인프라 각각의 구현 상세
- 개별 컴포넌트 내부의 기술적 의사결정(ADR), 기능 명세(Spec), 구현 계획(Plan)

## 다른 Repository와의 관계

| 구분 | 관리 위치 | 주요 다루는 내용 |
| :--- | :--- | :--- |
| **프로젝트 공통 (`my-space-docs`)** | 본 Repository | 제품 기획, 전체 요구사항, 상위 시스템 아키텍처, Repository 간 인터페이스 및 관계 |
| **프론트엔드 / 백엔드 / 인프라** | 각 Repository의 `/docs` | 해당 영역의 ADR, 세부 Spec, 구현 Plan 등 구현과 직접 관련된 문서 |

## 문서 관리 원칙

1. **필요 시점 생성**: 문서는 실제 필요성이 발생했을 때 생성하며, 향후 필요할 것이라는 이유로 빈 디렉터리나 문서를 미리 만들어 두지 않습니다.
2. **중복 최소화 및 참조**: 기존 문서나 다른 Repository의 `/docs`에서 다루는 내용과 중복을 피하고, 필요한 경우 해당 문서를 참조합니다.
3. **기존 기준 준수**: 프로젝트에 정의된 문서 작성 가이드와 템플릿을 따르며, 임의로 새로운 양식을 만들지 않습니다.
4. **사실 기반 기술**: 확인된 사실과 추정 또는 미결정 사항을 명확히 구분하여 기록합니다.

## 현재 디렉터리 구조 및 향후 문서 배치 기준

### 현재 구조

```text
my-space-docs/
├── README.md   # Repository 안내 및 문서 관리 기준
└── AGENTS.md   # AI Agent 작업 지침
```

### 향후 문서 배치 기준
- 실제 문서가 추가되는 시점에 문서의 성격(예: 제품 기획/요구사항, 전체 시스템 아키텍처, 문서 작성 가이드 등)에 맞춰 하위 디렉터리를 구성합니다.
- 분류 체계나 대규모 디렉터리 구조를 변경할 때는 사전 논의를 거쳐 반영합니다.
